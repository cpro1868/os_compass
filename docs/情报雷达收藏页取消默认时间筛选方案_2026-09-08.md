# 情报雷达“收藏”选项卡取消默认时间筛选优化方案

> 日期：2026-09-08 13:09  
> 状态：📋 需求与设计方案确认（未开始编码）  
> 责任模块：情报雷达 (`src/components/RadarInbox.tsx`)

---

## 一、问题背景与现象

### 1. 现状逻辑
在“情报雷达”页面中：
- 顶部搜索工具栏维护了起始日期 `searchStartDate` 与结束日期 `searchEndDate`，**组件初始化默认值硬编码为最近一周**（`getOneWeekAgo()` 到 `getToday()`）。
- 列表筛选逻辑 `filteredItems` 中对所有当前选项卡（`all` 全部、`unread` 未读、`starred` 收藏等）**无差别执行该日期区间过滤**：
  ```typescript
  const itemDate = item.published_at || item.fetched_at;
  if (itemDate) {
    if (searchStartDate && itemDate < searchStartDate) return false;
    if (searchEndDate) {
      const endDate = new Date(searchEndDate);
      endDate.setDate(endDate.getDate() + 1);
      if (itemDate > endDate.toISOString()) return false;
    }
  }
  ```

### 2. 产生的缺陷与负面体验
- 用户在情报雷达中收藏的项目，属于**永久性资产/个人收藏夹**属性。
- 但当用户点击切换到“收藏”选项卡时，因为默认带上了“最近一周”的日期过滤，**导致超过 7 天之前收藏的情报条目完全不可见**。
- 用户容易产生“我的收藏数据丢失了”或“收藏功能存在 Bug”的严重负面认知。

## 二、需求目标与业务认知原则

| 选项卡 | 业务属性 | 时间筛选行为规范 |
|---|---|---|
| **全部 (all)** | 动态资讯流 / 收件箱 | 默认受限于时效筛选（默认最近一周或用户设定），保障流转与浏览效率。 |
| **未读 (unread)** | 待处理待阅流 | 默认受限于时效筛选，专注于处理近期新鲜资讯。 |
| **收藏 (starred)** | **永久收藏夹 / 知识资产库** | **默认不限制时间范围（时间无上限、无下限）**，只要用户收藏过，不论何时采集/收藏的，全部默认完整展示！若用户在收藏页**主动**选择了具体日期范围，才按用户主动选择的日期筛选。 |

## 三、具象化设计方案

### 1. 核心筛选逻辑调整 (`filteredItems`)
在 `RadarInbox.tsx` 的计算过滤流中，为 `activeTab === 'starred'` 赋予特殊的时间语义判断：

```typescript
// 日期筛选：如果是“收藏”选项卡，且当前日期是系统默认赋予的“最近一周”，则忽略默认时间限制
const isDefaultWeekRange = searchStartDate === getOneWeekAgo() && searchEndDate === getToday();
const shouldApplyDateFilter = !(activeTab === 'starred' && isDefaultWeekRange);

if (shouldApplyDateFilter && itemDate) {
  if (searchStartDate && itemDate < searchStartDate) return false;
  if (searchEndDate) {
    const endDate = new Date(searchEndDate);
    endDate.setDate(endDate.getDate() + 1);
    if (itemDate > endDate.toISOString()) return false;
  }
}
```

### 2. 交互与 UI 细节协同优化（双向状态隔离与保护）
为了确保“收藏夹无时间限制”与“全部/未读原有时间限制”互不干扰，必须做到双向严格隔离：

1. **状态隔离与记忆恢复机制**：
   - 为“常规流（全部/未读）”与“收藏夹”分别维护各自独立的日期状态，或者在状态流转中显式记忆：
     - 用户在“全部/未读”下拥有的日期筛选范围（默认即为 `getOneWeekAgo()` 到 `getToday()`，或者用户在全部页临时自定义的日期范围），在切换离开时**予以保存记录**；
     - 当用户切换到 **“收藏 (starred)”** tab 时：
       - 日期起止输入框自动清空（`searchStartDate = ''`, `searchEndDate = ''`），界面清晰显示未设时间限制，列表展示该仓库下所有历史收藏，无论何时收藏均完整可见；
     - 当用户从“收藏”切换回 **“全部 (all)”** 或 **“未读 (unread)”** tab 时：
       - **必须无缝还原其原有的日期限制**（若用户之前未改动过，则严格恢复为系统默认的“最近一周” `getOneWeekAgo()` 到 `getToday()`；若用户之前曾主动选定过日期，则精准恢复其选定日期）；
       - **绝对不能因为在收藏页置空了日期，导致切回全部或未读时也变成了全部历史数据**！

2. **“重置”按钮上下文自适应**：
   - 在“收藏”选项卡下点击“重置”：仅清空关键字和来源，日期保持为空（不限时间）；
   - 在“全部/未读”选项卡下点击“重置”：严格重置恢复为默认的最近一周（`getOneWeekAgo()` 到 `getToday()`）。

3. **核心筛选逻辑精准执行**：
   - 在“全部/未读”下，必须严格按照生效中的起止日期过滤资讯时效；
   - 在“收藏”下，仅当 `searchStartDate` 或 `searchEndDate` 不为空（即用户主动指定日期）时才执行过滤，为空时对时间全放行。
