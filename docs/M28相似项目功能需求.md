## 1. 概述

### 1.1 目标

在项目详情中新增「相似项目」选项卡，为当前项目找出**语义或生态上相近**的其他项目，来源包括两部分：

- **本地**：当前仓库中已收录的项目（向量语义匹配为主，规则匹配兜底）；
- **网络**：按项目来源平台路由到对应平台的免费搜索接口（GitHub/Gitee/GitLab/NPM/Crates.io），PyPI 及无结果场景由 LLM 知识推荐兜底。

### 1.2 价值

| 痛点 | 解决方式 |
|------|----------|
| 评估一个项目时想横向对比同类，但靠自己回忆/搜索效率低 | 打开详情即可看到同类候选，含相似度依据 |
| 自己仓库里收录过的同类项目想不起来 | 本地语义匹配把沉睡资产翻出来 |
| 联网搜索容易踩到不存在/已废弃的项目 | 网络结果全部来自真实平台接口；LLM 推荐结果逐个做存在性校验 |
| 每次查看都调用接口，浪费限额和 Token | 网络结果按项目缓存，默认 7 天有效，手动刷新才重新请求 |

### 1.3 定位

- **入口**：项目详情弹窗第 11 个选项卡（… / 文章生成 / 项目探索 / **相似项目**）
- **边界**：
  - 本地部分只检索**当前仓库**（跟随仓库切换隔离）；
  - 网络部分只做"推荐发现"，不自动入库，需用户显式点击导入；
  - 不向任何第三方上传本地项目数据（LLM 兜底通道仅发送当前项目的名称+描述+语言，不发送笔记、用户信息等）。

## 2. 关键决策（2026-10-29 与用户确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 相似来源 | **本地 + 网络** 双通道（用户明确提出） |
| 2 | 平台覆盖 | **不限 GitHub**，Gitee/GitLab/NPM/Crates.io 平台搜索全部支持；PyPI 无官方搜索 API，走 LLM 兜底 |
| 3 | 费用约束 | 平台搜索接口**全部免费**（GitHub Search 匿名 10 次/分、带 Token 30 次/分；Gitee/GitLab/NPM/Crates 匿名可用）；LLM 兜底消耗用户自己的 LLM 额度；不新增任何收费依赖 |
| 4 | 结果可信度 | LLM 推荐的项目 URL 必须逐个校验真实存在（GitHub/Gitee 走 API HEAD，其他平台跳过校验直接标注"未验证"） |
| 5 | 缓存策略 | 网络结果按项目缓存于**仓库库**，有效期 7 天，手动刷新强制更新 |

### 安全红线

- ❌ 本地笔记、用户信息（数据保险箱）**绝不注入** LLM 兜底通道的 Prompt
- ❌ LLM/平台 Token 不落盘到任何文档/代码
- ✅ 相似结果缓存存**仓库库**（`os_compass.db`），跟随仓库切换隔离
- ✅ 本地相似匹配纯本地计算，无任何网络请求

## 3. 功能需求

### FR-01 选项卡入口

- 项目详情弹窗新增「相似项目」选项卡，位于「项目探索」之后
- 选项卡图标：`fa-solid fa-layer-group`（同类堆叠语义）
- i18n：zh「相似项目」/ en「Similar Projects」

### FR-02 页面结构

选项卡内分上下（或左右）两个区块：

1. **库内相似项目**（本地通道）
2. **网络相似项目**（网络通道，异步加载）

顶部工具条：当前通道状态徽标（向量检索/规则降级/缓存时间）+「刷新」按钮（仅刷新网络部分）。

### FR-03 本地相似匹配

- **主通道（向量）**：取当前项目已存储的 embedding 向量，与库内其他项目向量做余弦相似度，阈值过滤后取 Top 10（复用 `embedding.rs` 的 `cosine_similarity`，阈值参考现有 `SEMANTIC_SEARCH_MIN_SCORE`）
  - **不重新生成向量**、不调用 Embedding API，纯本地计算，毫秒级
  - 当前项目未向量化：显示引导提示 +「立即向量化该项目」按钮（单项目调用，1 次 Embedding 请求）
- **降级通道（规则）**：Embedding 未启用时，按 主语言相同 + 标签重叠数 + 同分类 加权打分，取 Top 10，界面标注「语义检索未启用，结果基于规则匹配」
- 每条结果展示：项目名称、描述、主语言、stars、相似度百分比；点击直接切换到该项目详情
- 排除项：排除项目自身；排除已软删除（data_status != 'ACTIVE'）项目

### FR-04 网络相似搜索（按来源平台路由）

按当前项目的 `source` 字段路由：

| 项目来源 | 通道 | 接口 | 构造查询 |
|----------|------|------|----------|
| github | GitHub Search API | `GET /search/repositories` | `topic:{t1}+topic:{t2}+language:{lang}` 按 stars 排序，取前 10；topics 缺失时退化为 `language:{lang}+项目名关键词` |
| gitee | Gitee 搜索 | `GET /api/v5/search/repositories` | `q=项目名关键词/描述关键词` |
| gitlab | GitLab 项目搜索 | `GET /api/v4/projects?search=` | `search=项目名关键词` |
| npm | NPM registry 搜索 | `GET /-/v1/search?text=` | `text=描述关键词` |
| crates | Crates.io 搜索 | `GET /api/v1/crates?q=` | `q=项目名关键词` |
| pypi / 其他 | LLM 兜底 | — | 见 FR-05 |

- 平台搜索请求遵守现有代理规则（`network_proxy` / `github_proxy`）
- GitHub 通道需要给 `GitHubRepo` 结构体补 `topics` 字段（当前未解析）
- 网络部分**异步加载**：打开选项卡立即显示本地结果，网络区块显示加载中，完成后填充；失败显示错误与「重试」按钮

### FR-05 LLM 兜底推荐

- 触发条件：PyPI/未知来源项目，或平台搜索返回 0 条结果（用户可点「试试 LLM 推荐」手动触发）
- Prompt 输入**仅限**：项目名称、描述、主语言（不注入 README、笔记、用户信息）
- 复用 `recommend_projects_with_llm()` 的结构化 JSON 解析逻辑
- 返回结果逐个校验存在性：
  - GitHub/Gitee URL：调用对应 API 校验（存在则顺带取 stars 补充展示）
  - 其他/无法识别的 URL：标注「未验证」徽标，展示但置灰警示
- 界面显著标注「LLM 推荐，请自行甄别」

### FR-06 结果缓存

- 仓库库新增表 `similar_projects_cache`：

```sql
CREATE TABLE IF NOT EXISTS similar_projects_cache (
  project_id   INTEGER PRIMARY KEY REFERENCES projects(id) ON DELETE CASCADE,
  channel      TEXT NOT NULL,          -- 'platform' | 'llm'
  results_json TEXT NOT NULL,          -- 序列化的结果数组
  created_at   TEXT NOT NULL
);
```

- 有效期 7 天；过期或手动点「刷新」时重新请求
- 本地相似结果**不缓存**（本地计算极快，实时算保证新鲜度）

### FR-07 结果操作

每条网络结果提供两个操作：

- **打开链接**：系统浏览器打开项目主页
- **导入仓库**：调用现有导入流程（复用 `import_project`），导入成功后该卡片标注「已入库」并可直接打开详情

本地结果：点击卡片即切换到该项目详情（关闭当前详情弹窗并打开目标项目）。

### FR-08 空态与异常

| 场景 | 表现 |
|------|------|
| 本地无任何相似项目 | 空态插画 + 「向量阈值较高，可在设置中调整」提示 |
| Embedding 未配置 | 本地区块走规则降级 + 黄色提示条 + 「前往设置」按钮 |
| 网络请求失败（限流/超时） | 网络区块显示错误原因 + 「重试」按钮，不影响本地区块 |
| LLM 未配置且走了兜底通道 | 显示「配置 LLM 后可用 LLM 推荐」+「前往设置」按钮 |

## 4. 非功能需求

- **性能**：本地匹配 < 200ms（1000 项目内）；网络区块异步，不阻塞选项卡打开
- **限额友好**：网络结果默认缓存 7 天；GitHub 搜索每次打开选项卡最多 1 次请求
- **国际化**：全部文案 zh/en 双语
- **暗色主题**：与详情页其他选项卡一致支持暗色

## 5. 技术要点（供实施参考）

| 模块 | 复用/新增 |
|------|-----------|
| 本地向量匹配 | 新增 `find_similar_projects(project_id, limit)`，复用 `cosine_similarity`、`project_embeddings` 表 |

| GitHub 搜索 | 新增 `search_github_similar()`，给 `GitHubRepo` 补 `topics` 字段 |

| 存在性校验 | 复用各平台 fetch 的轻量 HEAD/GET |
| 缓存 | 仓库库新表 `similar_projects_cache` |
| 前端 | 新增 `SimilarPanel` 组件；`ProjectDetailDialog` tabs 数组加一项；i18n 键 `detail.similar` 等 |

## 6. 验收标准

1. 打开任意已向量化项目的详情 → 「相似项目」选项卡 → 本地区块 1 秒内展示带相似度的项目列表
2. Embedding 未配置时本地区块降级为规则匹配并显示黄色提示条
3. GitHub 项目：网络区块展示真实仓库结果，且包含 topics 匹配依据
4. NPM/Crates 项目：网络区块走对应平台搜索
5. PyPI 项目：网络区块提供「LLM 推荐」入口，推荐结果经存在性校验
6. 7 天内再次打开同一项目：网络结果秒出（读缓存），显示缓存时间；点刷新强制更新
7. 网络结果可一键导入仓库，导入后卡片状态变为「已入库」
8. 断网时：本地区块正常工作，网络区块显示错误+重试
