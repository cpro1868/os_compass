## 2 仓库路径修复（严重BUG）

### 2.1 问题描述

**BUG**：仓库库被错误地放在了系统库目录下，违反设计规范。

### 2.2 系统库与仓库库规范

| 类型 | 获取 API | 作用 |
|------|----------|------|
| **系统库** | `BaseDirs.data_dir().join(".os-compass")` | 全局共享数据（插件、雷达、系统设置） |
| **仓库库** | `app.path().app_data_dir().join("vaults")` | 项目私有数据 |

### 2.3 问题代码 (lib.rs)

仓库相关代码错误使用了 `app.path().app_data_dir()`，导致仓库库被放在了系统库目录下。

### 2.4 修复方案

1. **代码修复**：修改仓库路径获取逻辑
2. **数据迁移**：将现有仓库数据迁移到正确位置

### 2.5 迁移方案

```
源：C:\Users\Administrator\AppData\Roaming\.os-compass\
目标：C:\Users\Administrator\AppData\Local\com.administrator.os-compass\vaults\default\

迁移文件：
├── os_compass.db      ← 仓库数据库
└── .cryptokey         ← 仓库独立密钥（必须迁移，否则数据无法解密）
```

**注意**：`.cryptokey` 必须与数据库一起迁移，否则仓库数据无法解密。

迁移步骤：
1. 检测仓库是否在错误位置（`Roaming\.os-compass\os_compass.db`）
2. 创建目标目录结构
3. 复制数据库文件 `os_compass.db`
4. 复制加密密钥 `.cryptokey`（必须！）
5. 更新 `vault-index.json` 路径
6. 更新 `last-vault.txt` 路径
7. 验证迁移成功

### 2.6 修复文件

- `src-tauri/src/lib.rs` - 路径获取逻辑
- `src-tauri/src/vault.rs` - 仓库迁移逻辑

## 3 用户信息模块（数据保险箱）

### 3.1 功能定位

为每个开源项目存储项目相关的私密信息（如 Token、API Key、账户密码等）。

**数据库表**：`project_user_info`（已存在）

```sql
CREATE TABLE project_user_info (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    info_key TEXT NOT NULL,
    info_value TEXT,
    is_secret BOOLEAN DEFAULT FALSE,
    remark TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(project_id, info_key)
);
```

### 3.2 功能设计

| 功能 | 说明 |
|------|------|
| 列表展示 | 已添加的 key-value 条目 |
| 添加/编辑 | key + value + 敏感开关 + 备注 |
| 删除 | 移除条目 |
| 复制 | 点击复制 value 到剪贴板 |

### 3.3 字段说明

| 字段 | 内容 | 存储 | 展示 | 复制 |
|------|------|------|------|------|
| `info_key` | 用户自定义 | 明文 | 明文 | - |
| `info_value` | 值 | 敏感→加密，明文→明文 | 敏感→脱敏，明文→Markdown | ✅ |
| `remark` | 备注 | 明文 | 明文 | - |

### 3.4 参照

- 原型：`design-system/public/project-detail.html`（用户信息标签页区域）

## 5 广告过滤插件

### 5.1 功能定位

情报雷达采集时自动过滤广告和垃圾信息。

**技术方案**：
- **核心库**：banlex（Rust 词库检测库）
- **GitHub**：https://github.com/cognis-digital/banlex
- **混淆检测**：支持 leetspeak、homoglyph、零宽字符
- **内置分类**：spam/scam/harassment
- **中文扩展**：针对 Telegram 和国内平台优化

### 5.2 强度定义

| 强度 | 阈值 | 说明 |
|------|------|------|
| 关闭 | - | 不过滤任何内容 |
| 低 | 2.0 | 只过滤明显广告 |
| 中 | 1.0 | **标准过滤（推荐）** |
| 高 | 0.5 | 激进过滤，可能误杀 |

### 5.3 中文扩展词库

| 分类 | 示例词汇 |
|------|----------|
| 广告类 | 加微信、扫码关注，二维码 |
| 营销类 | 联系我、收徒、培训、课程、优惠券 |
| 行动类 | 立即、点击、限时、福利 |

### 5.4 过滤流程

```
采集内容 → banlex 评分 → 评分 >= 阈值 → 过滤丢弃
                          ↓
                     评分 < 阈值 → 通过检测 → 入库
```

### 5.5 参照

- 原型：`design-system/public/radar-filter-settings.html`

### Task 5: banlex 集成 + 中文词库

**⚠️ 需要重构**

**问题**：banlex 库不在 crates.io 上，需要从 GitHub 添加。

**正确的库信息**：
- 名称：banlex
- 仓库：https://github.com/cognis-digital/banlex
- 特点：
  - 支持自定义词库（JSON 格式）
  - 支持混淆检测（leetspeak、Cyrillic、同形字）
  - 支持严重程度评分
  - 支持上下文策略
  - 默认词库仅支持英语、西班牙语、法语、德语

**Files:**
- Modify: `src-tauri/Cargo.toml`
- Modify: `src-tauri/src/plugins/radar.rs`

**Step 1: 添加依赖**
```toml
# Cargo.toml
[dependencies.banlex]
git = "https://github.com/cognis-digital/banlex"
```

**Step 2: 集成 API**
```rust
use banlex::{Scanner, Lexicon, default_lexicon};

let scanner = Scanner::new(default_lexicon(), 1.0);
let result = scanner.scan(content);
if result.flagged {
    // 过滤
}
```

**Step 3: 创建中文词库**

需要创建 JSON 格式的中文词库文件：
```json
{
  "categories": {
    "spam": {
      "severity": "medium",
      "rules": [
        {"id": "ZH-SPAM-001", "pattern": "加微信", "severity": "high"},
        {"id": "ZH-SPAM-002", "pattern": "扫码关注", "severity": "high"},
        {"id": "ZH-SPAM-003", "pattern": "优惠", "severity": "medium"}
      ]
    }
  }
}
```

**词库需求**：
| 类别 | 关键词示例 |
|------|-----------|
| VPN/代理 | 翻墙、机场、梯子、节点、线路、三网、解锁 |
| 电报群 | 官方频道、官方群组、进群 |
| AI/流媒体 | ChatGPT、Claude、Gemini、Netflix、Disney |
| 营销 | 优惠、限时福利、立即体验、免费送 |
