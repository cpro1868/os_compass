## 二、迁移功能测试

### TC-V2.0-001：首次启动自动迁移

**目的**：验证首次启动 V2.0 时，旧配置能自动迁移到系统级数据库

**前置条件**：
- 存在 V1.x 创建的仓库目录
- 仓库包含 `app_settings` 表数据（LLM 配置、代理设置等）

**测试步骤**：
1. 保留旧的仓库目录（包含 `os_compass.db`）
2. 启动 V2.0 应用
3. 观察迁移日志或提示

**预期结果**：
- 应用提示用户有旧配置需要迁移
- 用户确认后，旧配置迁移到系统级数据库
- 迁移完成后，配置在系统级 `system_settings.db` 中

**通过标准**：系统级数据库 `app_settings` 表包含原有配置

---

### TC-V2.0-002：Token 加密迁移

**目的**：验证 Token 类凭据能正确加密迁移

**前置条件**：
- 旧仓库包含 `system_variables` 表数据
- 包含 `github_token`、`gitee_token` 等凭据

**测试步骤**：
1. 记录旧 Token 值（加密状态）
2. 执行迁移
3. 在系统级 `system_vars.db` 中查询迁移后的 Token

**预期结果**：
- Token 以密文形式存储在 `encrypted_value` 字段
- Token 可以通过解密恢复为原文
- `is_secret` 字段正确设置（Token = 1）

**通过标准**：`is_secret = 1` 且 `encrypted_value` 非空

---

### TC-V2.0-003：配置完整性验证

**目的**：验证迁移后所有配置项都存在

**前置条件**：旧仓库包含完整配置

**测试步骤**：
1. 记录旧仓库的配置项列表
2. 执行迁移
3. 查询系统级数据库的配置项
4. 对比配置项数量和内容

**预期结果**：

| 配置项 | 迁移前位置 | 迁移后位置 |
|--------|-----------|-----------|
| theme | `settings.theme` | `app_settings.key = 'settings.theme'` |
| language | `settings.language` | `app_settings.key = 'settings.language'` |
| llm_api_base | `settings.llm_api_base` | `app_settings.key = 'settings.llm_api_base'` |
| llm_model | `settings.llm_model` | `app_settings.key = 'settings.llm_model'` |
| proxy_enabled | `settings.proxy_enabled` | `app_settings.key = 'settings.proxy_enabled'` |
| github_token | `system_variables.github_token` | `system_variables.github_token` |
| gitee_token | `system_variables.gitee_token` | `system_variables.gitee_token` |

**通过标准**：配置项数量和内容一致

---

### TC-V2.0-004：迁移回滚

**目的**：验证迁移失败时能正确回滚

**前置条件**：
- 旧仓库配置完整
- 准备迁移中断条件（如磁盘空间不足）

**测试步骤**：
1. 执行迁移
2. 人为中断迁移过程
3. 检查旧仓库配置是否完整
4. 检查系统级数据库是否残留脏数据

**预期结果**：
- 旧仓库配置保持不变
- 系统级数据库无残留数据或被清理
- 用户可重新执行迁移

**通过标准**：旧数据完整性保持

---

### TC-V2.0-005：重复迁移防护

**目的**：验证重复迁移不会导致数据重复或丢失

**前置条件**：已完成一次迁移

**测试步骤**：
1. 检查 `system_migration_info` 表记录
2. 重新打开应用
3. 尝试再次迁移

**预期结果**：
- `system_migration_info` 表有迁移记录
- 系统检测到已迁移，跳过迁移步骤
- 配置数据不重复

**通过标准**：迁移记录存在且数据不重复

### TC-V2.0-009：仓库切换配置保持

**目的**：验证切换仓库后配置不丢失

4. 切换回仓库 A

**目的**：验证新建仓库不需要迁移

**前置条件**：系统级数据库已存在

**测试步骤**：
1. 创建一个新仓库
2. 检查 `system_migration_info` 表
3. 检查新仓库的 `app_settings` 表

**预期结果**：
- 新仓库 `app_settings` 表为空或使用默认值
- 系统使用系统级配置
- 不触发迁移

**通过标准**：新建仓库不触发迁移

## 四、安全测试

### TC-V2.0-011：Token 不泄露

**目的**：验证 Token 不存储在仓库中

**前置条件**：迁移完成

**测试步骤**：
1. 检查仓库 `os_compass.db` 的 `system_variables` 表
2. 检查仓库 `os_compass.db` 的 `app_settings` 表
3. 检查仓库目录下的其他文件

**预期结果**：
- 仓库 `system_variables` 表无 Token 或为空
- 仓库 `app_settings` 表无敏感信息
- Token 只存在于系统级 `system_vars.db`

**通过标准**：Token 不在仓库中

---

### TC-V2.0-012：加密存储验证

**目的**：验证 Token 以密文存储

**前置条件**：Token 已迁移

**测试步骤**：
1. 查询 `system_vars.db` 的 `system_variables` 表
2. 检查 `github_token` 的 `encrypted_value` 字段

**预期结果**：
- `encrypted_value` 不是明文 Token
- `encrypted_value` 是 Base64 编码或密文

**通过标准**：`encrypted_value` 不包含明文 Token
