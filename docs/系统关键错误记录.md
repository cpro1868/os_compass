# 系统关键错误记录

本文档记录 OS-Compass 项目中曾经犯过的关键错误、根本原因和解决方案。**所有开发者必须阅读并永远记住**，避免重蹈覆辙。

## 🚨 致命错误 #004：Git 版本回滚导致功能丢失

### 问题
侧边栏仓库图标合并功能丢失，已合并的代码被 revert 回分开状态

### 影响时间
2026-07-12

### 根本原因
Git 历史中存在 revert commit (0606553)，将合并的代码回滚：
```
93bd19a feat: merge category and tag management  ← 合并
0606553 revert: restore original CategoryManager  ← 回滚！
d0d4c17 refactor: merge CategoryManager into OrganizationManager
```

### 教训（必须永远记住）
1. **不要随意 revert** - 功能代码除非确定废弃，否则不要 revert
2. **合并后验证** - 合并操作后必须验证功能正常
3. **审查提交** - 提交前检查变更内容，确保不是回滚已有功能
4. **分支保护** - 重要功能使用独立分支，开发完成后再合并

### 预防措施
1. 提交前使用 `git diff` 检查变更
2. 合并前在独立分支开发
3. 重要功能添加测试用例
4. 提交信息明确说明功能目的

## 🚨 致命错误 #001：跨库数据库查询

### 问题
情报雷达页面显示空白，报错：`no such table: radar_sources`

### 影响版本
v1.0.0 (2026-07-19)

### 根本原因
**情报雷达的数据存储在两个不同的数据库中**：

| 数据 | 数据库 | 表名 |
|------|--------|------|
| 采集数据 | `plugin_radar.db`（仓库库） | `radar_items` |
| 信息源配置 | `plugins.db`（系统库） | `radar_sources` |

修改 SQL 查询时错误地使用了 `LEFT JOIN` 尝试跨库关联，但 **SQLite 不支持跨数据库 JOIN**，导致查询系统库中的表时报错。

### 错误代码
```rust
// ❌ 致命错误：跨库 JOIN（SQLite 不支持）
format!(
    "SELECT r.id, r.source_id, s.name as source_name \
     FROM radar_items r \
     LEFT JOIN radar_sources s ON r.source_id = s.id \
     ..."
)
```

### 正确解决方案
**分两步查询，在应用层合并数据**：

```rust
// ✅ 步骤1：从仓库库查询 radar_items
let rows = conn.query_map([], |row| {
    Ok(RadarItem {
        id: row.get(0)?,
        source_id: row.get(1)?,
        source_name: None, // 暂时为 None
        project_name: row.get(2)?,
        // ...
    })
})?;

// ✅ 步骤2：从系统库查询信息源名称（循环中单独查询）
for row in rows {
    let mut item = row?;
    if let Ok(name) = PLUGIN_CONFIG_DB.get_radar_source_name(item.source_id) {
        item.source_name = Some(name);
    }
    items.push(item);
}
```

### 数据库路径参考
- **系统库**：`%APPDATA%\.os-compass\plugins.db`
- **仓库库**：`%APPDATA%\.os-compass\plugin_radar.db`

### 教训（必须永远记住）
1. **SQLite 不支持跨数据库 JOIN** - 不要尝试
2. 修改数据库查询前，**必须确认表所在的数据库**
3. 涉及多数据库时，使用**应用层合并**而不是 SQL JOIN
4. 情报雷达功能涉及两个数据库，涉及修改时需特别小心

### 提交记录
- 引入错误：d018b3f（feat: radar - add source name...）
- 修复错误：d0463b8（fix: radar - query radar_items from vault db, source_name from system db separately）

## 🚨 致命错误 #002：Tauri 命令未注册

### 问题
前端调用 `getSupportedPlatformDomains()` 报错：命令不存在

### 根本原因
在 `extensions.rs` 中添加了新命令函数，但**未在 `lib.rs` 的命令注册列表中添加**

### 错误代码
```rust
// extensions.rs - 添加了命令
#[tauri::command]
pub fn get_supported_platform_domains() -> Result<Vec<String>, String> {
    // ...
}
```

```rust
// lib.rs - ❌ 忘记注册
commands::list_extensions,
commands::get_extension,
commands::set_extension_enabled,
commands::get_enabled_extensions,
// 缺少：commands::get_supported_platform_domains,
```

### 正确做法
```rust
// lib.rs - ✅ 必须注册
commands::list_extensions,
commands::get_extension,
commands::set_extension_enabled,
commands::get_enabled_extensions,
commands::get_supported_platform_domains, // ← 添加这一行
```

### 教训（必须永远记住）
1. 新增 Tauri 命令后，**必须在 `lib.rs` 中注册**
2. 注册位置：`run()` 函数中 `.invoke_handlers()` 部分
3. 忘记注册会导致运行时错误，但编译不会报错

## 🚨 致命错误 #003：插件启用状态硬编码

### 问题
所有插件（情报雷达等）显示为禁用状态

### 根本原因
`plugin_manager.rs` 中硬编码 `enabled: false`

### 错误代码
```rust
// ❌ 硬编码为 false
let info = PluginInfo {
    id: plugin.id().to_string(),
    enabled: false, // ← 错误
    // ...
};
```

### 正确代码
```rust
// ✅ 从数据库读取
let info = PluginInfo {
    id: plugin.id().to_string(),
    enabled: PLUGIN_CONFIG_DB.get_enabled(plugin.id()), // ← 正确
    // ...
};
```

### 教训（必须永远记住）
1. 配置状态应从数据库读取，**不要硬编码**
2. 插件启用状态存储在 `plugins.db` 的 `system_plugins` 表中

## 🚨 致命错误 #005：雷达数据存储位置放错目录

### 问题
情报雷达数据存储位置错误

### 正确设计（需求明确）
```
情报雷达数据存储架构：

┌─────────────────────────────────────────────────────────┐
│ 系统库 plugins.db                                          │
│  - radar_sources（情报源信息）                             │
│  - 操作：新增/修改/删除/读取                               │
└─────────────────────────────────────────────────────────┘
                          ↓ 扫描时读取
┌─────────────────────────────────────────────────────────┐
│ 当前仓库 plugin_radar.db                                   │
│  - radar_items（采集的数据）                                │
│  - 操作：写入采集数据 / 读取展示                            │
└─────────────────────────────────────────────────────────┘
```

| 操作 | 数据位置 | 说明 |
|------|---------|------|
| 信息源 CRUD | 系统库 `plugins.db` | 全局共享 |
| 采集数据 | 当前仓库 | 跟随仓库切换 |

### 教训（必须永远记住）
1. 信息源在系统库，采集数据在仓库库
2. **切换仓库时，采集清单必须跟随变化**

## 🚨 致命错误 #007：仓库切换时未调用插件生命周期方法

### 问题
切换仓库后情报雷达无法加载数据

### 发生时间
2026-07-19

### 根本原因
`open_vault` 没有调用插件的生命周期方法

### 正确流程（插件接入规范 §4.3）
```
用户切换仓库
  → 遍历所有已启用插件
    → 调用 plugin.on_disable(context)   // 停止旧仓库后台任务
  → 切换主库 DATABASE
  → 遍历所有已注册插件
    → 构建 new PluginContext
    → 调用 plugin.init(new_context)     // 初始化新仓库插件库
    → 如果 enabled=true → 调用 plugin.on_enable(new_context)
```

### 教训（必须永远记住）
1. 仓库切换必须触发插件的 `on_disable` → `init` → `on_enable` 生命周期
2. 修改前必须阅读完整的需求和设计文档
3. 不确定时要读文档，不要瞎猜
