## 一、问题背景与改造范围

### 1.1 当前问题

当前项目存在**配置存储架构混乱**：
- `app_settings` 表和 `system_variables` 表都在**仓库数据库**中
- 切换仓库后，LLM 配置、代理设置、Token 凭据会丢失
- Token 凭据可能随仓库分享泄露

### 1.2 V2.0 改造目标

| 配置类型 | 当前存储位置 | V2.0 目标位置 | 说明 |
|----------|-------------|--------------|------|
| 系统配置（LLM、代理、翻译等） | 仓库数据库 `app_settings` | `%APPDATA%/os-compass/system_settings.db` | 系统级，切换仓库不丢失 |
| 凭据配置（Token、API Key） | 仓库数据库 `system_variables` | `%APPDATA%/os-compass/system_vars.db` | 系统级，加密存储 |
| 插件配置（雷达、搜索等） | 仓库数据库 `feature_plugins` | **保持仓库级** | 与仓库关联 |

**数据库设计**：

```sql
-- system_settings.db
CREATE TABLE system_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at TEXT DEFAULT (datetime('now', 'localtime'))
);

-- system_vars.db  
CREATE TABLE system_variables (
    key TEXT PRIMARY KEY,
    encrypted_value TEXT NOT NULL,  -- AES-256-GCM 加密
    is_secret INTEGER DEFAULT 0,
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

**迁移触发时机**：
- 首次启动 V2.0
- 打开旧版创建的仓库

**迁移流程**：
```
1. 检测旧配置（vault/os_compass.db 存在 app_settings 或 system_variables 表）
2. 备份旧配置到 backup/YYYYMMDD_*.db
3. 创建系统级数据库（system_settings.db, system_vars.db）
4. 读取 app_settings，解密凭据，写入系统级
5. 标记迁移完成（settings.migration_version = '2.0'）
6. 可选：删除旧配置字段
```

## 四、风险与注意事项

### 4.1 风险矩阵

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 迁移失败导致数据丢失 | 高 | 低 | 迁移前自动备份，失败回滚 |
| 加密密钥不匹配导致 Token 丢失 | 高 | 低 | 添加密钥验证，保留旧配置 |
| 旧仓库兼容性问题 | 中 | 中 | 提供迁移跳过选项 |
| 配置读取路径遗漏 | 高 | 低 | 全面代码审查 + 回归测试 |
| 迁移时机判断错误 | 中 | 低 | 多重检测机制 |

### 4.2 注意事项

1. **向后兼容**：迁移后仍需支持旧仓库（用户可能回滚版本）
2. **加密密钥**：确保主密钥在系统级存储中正确初始化
3. **并发安全**：多仓库切换时的配置读写安全
4. **日志诊断**：迁移失败时提供足够的诊断信息
