## 一、系统改造（V2.0 配置迁移）

### 1.1 问题背景

当前项目存在**配置存储架构混乱**：
- `app_settings` 表和 `system_variables` 表都在**仓库数据库**中
- 切换仓库后，LLM 配置、代理设置、Token 凭据会丢失
- Token 凭据可能随仓库分享泄露

### 1.2 改造目标

| 配置类型 | 当前存储位置 | V2.0 目标位置 | 说明 |
|----------|-------------|--------------|------|
| 系统配置（LLM、代理、翻译等） | 仓库 `app_settings` 表 | `%APPDATA%/os-compass/system_settings.db` | 系统级 |
| 凭据配置（Token、API Key） | 仓库 `system_variables` 表 | `%APPDATA%/os-compass/system_vars.db` | 系统级，加密 |
| 插件配置（雷达、搜索等） | 仓库 `feature_plugins` 表 | **保持仓库级** | 与仓库关联 |

### 1.3 涉及改造的文件

### 2.3 固定网页监控适配器

#### 2.3.1 功能设计

```
┌─────────────────────────────────────────────────────────────┐
│ 固定网页监控适配器                                            │
├─────────────────────────────────────────────────────────────┤
│ source_type: 'web_monitor'                                  │
│ 配置参数：                                                   │
│   - url: 网页 URL（必填）                                    │
│   - selector: CSS 选择器（可选，指定监控元素）                 │
│   - check_interval: 检查间隔（秒，默认 3600）                 │
│   - content_hash: 上次抓取的 hash（内部使用）                │
│   - proxy_enabled: 是否使用代理                               │
└─────────────────────────────────────────────────────────────┘
```

#### 2.3.2 工作流程

```
1. 用户配置目标网页 URL
2. 按 check_interval 定时抓取
3. 比较内容 hash 判断是否有变化
4. 如有变化，提取链接和内容
5. 返回 RadarItem 列表
```
