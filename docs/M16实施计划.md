## 2 初始化向导

### 2.1 功能概述

系统首次启动或需要切换仓库时，引导用户完成仓库的创建、选择或导入。

**核心价值**：
- **本地优先**：用户掌控数据，仓库位置由用户选择
- **零门槛**：简单直观，3步完成初始化
- **数据迁移**：支持从备份恢复

### 2.2 功能定位

类似 Obsidian 首次启动时的仓库选择界面，提供三种仓库获取方式：
1. **选择已有仓库**：打开之前创建的仓库
2. **创建新仓库**：新建本地仓库
3. **从备份导入**：恢复之前导出的仓库

### 2.3 触发条件

| 场景 | 说明 |
|------|------|
| **首次启动** | 系统首次启动时（无 last-vault.txt） |
| **无仓库状态** | 所有仓库都被删除后 |
| **手动入口** | 侧边栏/设置中提供入口，随时可进入 |

### 2.4 系统入口

| 触发方式 | 场景 | 说明 |
|----------|------|------|
| **自动触发** | 首次启动 | 系统首次启动时（无仓库） |
| **自动触发** | 无仓库状态 | 所有仓库都被删除后 |
| **手动入口** | 侧边栏 | 侧边栏最下方（设置的下面） |

**手动入口位置**：
```
侧边栏
├── 📊 看板视图
├── 📋 列表视图
├── 📁 归档
├── 📈 统计
├── 🔧 设置
├── 🗂️ 切换仓库 ← 当前入口
└── 🚪 初始化向导 ← 新增入口（设置的下面）
```

**说明**：即使当前已有仓库，也能在侧边栏底部找到"初始化向导"入口，方便测试。

### 2.6 功能详情

#### 2.6.1 选择已有仓库

| 项目 | 说明 |
|------|------|
| 列表展示 | 显示所有已创建的仓库（名称、路径、项目数） |
| 点击选择 | 直接打开该仓库，进入系统 |
| 空状态 | 无已有仓库时，提示创建或导入 |

#### 2.6.2 创建新仓库

| 项目 | 说明 |
|------|------|
| 仓库名称 | 用户输入，默认"我的仓库" |
| 存储位置 | 用户选择，默认 `vaults/` 目录下 |
| 目录验证 | 检测目标目录是否已有仓库 |
| 创建并继续 | 创建仓库，进入步骤2初始化 |

#### 2.6.3 从备份导入

| 子步骤 | 说明 |
|--------|------|
| 选择备份 | 选择包含备份的目录（必须有 `os_compass.db` 和 `.cryptokey`） |
| 验证备份 | 检测备份文件完整性，显示验证结果 |
| 选择目标 | 选择导入到哪个目录 |
| 执行导入 | 复制备份文件到目标位置 |

#### 2.6.4 初始化仓库

| 步骤 | 说明 |
|------|------|
| 创建文件夹 | 在目标位置创建仓库目录 |
| 初始化数据库 | 创建 `os_compass.db` 和表结构 |
| 设置加密密钥 | 生成/复制 `.cryptokey` 文件 |
| 注册仓库 | 写入 last-vault.txt 和 vault-index.json |

### 2.7 数据结构

#### 2.7.1 仓库索引 (vault-index.json)

```json
{
  "version": 1,
  "vaults": [
    {
      "name": "工作仓库",
      "path": "D:\\Projects\\vaults\\work",
      "created_at": "2026-07-01T10:00:00Z"
    }
  ]
}
```

#### 2.7.2 备份验证结果

```typescript
interface BackupValidation {
  valid: boolean;
  error?: string;
  db_exists: boolean;
  key_exists: boolean;
  project_count?: number;
}
```

### 2.8 错误处理

| 场景 | 错误信息 | 处理方式 |
|------|----------|----------|
| 目录已存在仓库 | "该目录已是仓库目录" | 提示选择其他目录 |
| 备份目录无效 | "未找到有效的备份文件" | 提示检查目录 |
| 备份验证失败 | "缺少必要的备份文件" | 提示缺少哪些文件 |
| 目标目录不存在 | "目录不存在" | 自动创建或提示创建 |
| 权限不足 | "无法写入目标目录" | 提示选择其他目录 |

### 2.9 交互说明

| 操作 | 行为 |
|------|------|
| 点击已有仓库 | 直接打开该仓库，进入系统 |
| 点击"创建并继续" | 进入步骤2初始化流程（新建） |
| 点击"开始导入" | 进入步骤1.5导入流程 |
| 浏览备份目录 | 打开系统目录选择对话框 |
| 点击"验证备份" | 检测 `os_compass.db` 和 `.cryptokey` |
| 选择目标位置 | 选择导入到哪个目录 |
| 点击"开始导入" | 复制备份到目标位置 |
| 点击"返回" | 返回步骤1 |
| 点击"上一步" | 返回步骤1，修改仓库名称或位置 |
| 点击"下一步" | 执行初始化，完成后进入步骤3 |
| 点击"开始使用" | 初始化完成，进入系统 |

## 9 异常处理和日志保障

### 9.1 问题背景

M15 阶段发现 AI 重新分析功能卡死 30+ 秒，根因是 JSON 解析代码块时切片范围计算错误：
```rust
// 当 find("```") 返回相对偏移 0 时
json_str = json_str[start + 7..start + end];
// = json_str[7..0] ← 无效范围！
```

**暴露的问题**：
| 问题 | 影响 |
|------|------|
| release 模式 `println!` 不输出 | 日志无法观察 |
| 切片操作无边界检查 | 程序行为未定义 |
| 错误未及时反馈 | 用户看到 loading 状态 |
| 错误类型不统一 | 前端难以处理 |

### 9.2 Task 15: 替换所有 `unwrap()` 为 `?` + 错误处理

**目标**：防止 `panic`，确保错误可恢复

**检查范围**：
```bash
# 查找所有 unwrap/expect
rg "\.(unwrap|expect)\(" --type rust
```

**修复示例**：
```rust
// ❌ 错误
let value = option.unwrap();

// ✅ 正确
let value = option.ok_or_else(|| MyError::InvalidInput("value is None".to_string()))?;
```

### 9.3 Task 16: 统一使用 `log` crate 替代 `println!`

**目标**：确保 release 模式日志正常输出

**修复示例**：
```rust
// ❌ 错误

// ✅ 正确

**日志级别**：
| 级别 | 使用场景 |
|------|----------|
| ERROR | JSON 解析失败、数据库连接失败 |
| WARN | 配置缺失、使用默认值 |
| INFO | 函数入口、重要流程节点 |
| DEBUG | 变量值、中间状态 |

use rusqlite::Connection;

pub struct ArticlePrompts;

impl ArticlePrompts {
    pub fn init_system_db(system_db: &Connection) -> Result<(), String> {
        system_db.execute(
            "CREATE TABLE IF NOT EXISTS article_prompts (
                style VARCHAR(50) PRIMARY KEY,
                prompt TEXT NOT NULL
            )",
            [],
        ).map_err(|e| e.to_string())?;

        // 插入内置模板
        Self::insert_default_templates(system_db)?;
        Ok(())
    }

    fn insert_default_templates(conn: &Connection) -> Result<(), String> {
        let templates = vec![
            ("tech_popular", include_str!("../prompts/tech_popular.txt")),
            ("business", include_str!("../prompts/business.txt")),
            ("tech_blog", include_str!("../prompts/tech_blog.txt")),
            ("brief", include_str!("../prompts/brief.txt")),
            ("humor", include_str!("../prompts/humor.txt")),
        ];

        for (style, prompt) in templates {
            conn.execute(
                "INSERT OR REPLACE INTO article_prompts (style, prompt) VALUES (?1, ?2)",
                [style, prompt],
            ).map_err(|e| e.to_string())?;
        }
        Ok(())
    }

    pub fn get_prompt(conn: &Connection, style: &str) -> Result<String, String> {
        conn.query_row(
            "SELECT prompt FROM article_prompts WHERE style = ?1",
            [style],
            |row| row.get(0),
        ).map_err(|e| format!("未找到风格 {} 的 Prompt", style))
    }
}
```

```rust
pub struct ArticleService;

impl ArticleService {
    pub async fn generate(
        project_id: i64,
        style: &str,
        word_count: &str,
    ) -> Result<String, String> {
        // 1. 从仓库库读取项目信息
        let project = Self::get_project(project_id)?;

        // 2. 从仓库库读取 README
        let readme = Self::get_readme(project_id)?;

        // 3. 从仓库库读取 AI 分析结果
        let ai_analysis = Self::get_ai_analysis(project_id)?;

        // 4. 从系统库读取 Prompt 模板
        let prompt_template = Self::get_prompt_template(style)?;

        // 5. 填充变量
        let prompt = Self::fill_variables(
            &prompt_template,
            &project,
            &readme,
            &ai_analysis,
            word_count,
            style,
        )?;

        // 6. 调用 LLM
        let article = llm::call(&prompt).await?;

        Ok(article)
    }

    fn fill_variables(
        template: &str,
        project: &Project,
        readme: &str,
        ai_analysis: &AiAnalysis,
        word_count: &str,
        style: &str,
    ) -> Result<String, String> {
        let use_cases = ai_analysis.use_cases.join("、");
        let readme_excerpt = &readme[..readme.len().min(2000)];

        Ok(template
            .replace("{project_name}", &project.name)
            .replace("{description}", &project.description)
            .replace("{use_cases}", &use_cases)
            .replace("{readme_excerpt}", readme_excerpt)
            .replace("{word_count}", word_count)
            .replace("{style}", style))
    }
}
```

use fullbleed::{PdfRender, RenderOptions};
use pulldown_cmark::{html, Parser};

fn markdown_to_pdf(markdown: &str, output_path: &str) -> Result<(), String> {
    // 1. Markdown → HTML
    let parser = Parser::new(markdown);
    let mut html_output = String::new();
    html::push_html(&mut html_output, parser);

    // 2. 包装为完整 HTML
    let full_html = format!(
        r#"<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<style>
body {{ font-family: system-ui, sans-serif; line-height: 1.6; padding: 40px; }}
h1 {{ color: #333; }} h2 {{ color: #555; margin-top: 1.5em; }}
code {{ background: #f5f5f5; padding: 2px 4px; border-radius: 3px; }}
pre {{ background: #f5f5f5; padding: 1em; overflow-x: auto; }}
</style>
</head>
<body>{}</body>
</html>"#,
        html_output
    );

    // 3. HTML → PDF
    let options = RenderOptions::default();
    PdfRender::new()
        .render_str(&full_html, &options)
        .map_err(|e| e.to_string())?
        .save(output_path)
        .map_err(|e| e.to_string())?;

    Ok(())
}
```
