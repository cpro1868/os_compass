## 2 初始化向导

### 2.1 功能概述

系统首次启动或需要切换仓库时，引导用户完成仓库的创建、选择或导入。

**核心价值**：
- **本地优先**：用户掌控数据，仓库位置由用户选择
- **零门槛**：简单直观，3步完成初始化
- **数据迁移**：支持从备份恢复

### 2.2 功能定位

类似 Obsidian 首次启动时的仓库选择界面，提供三种仓库获取方式：
1. **选择已有仓库**：打开之前创建的仓库
2. **创建新仓库**：新建本地仓库
3. **从备份导入**：恢复之前导出的仓库

### 2.3 触发条件

| 场景 | 说明 |
|------|------|
| **首次启动** | 系统首次启动时（无 last-vault.txt） |
| **无仓库状态** | 所有仓库都被删除后 |
| **手动入口** | 侧边栏/设置中提供入口，随时可进入 |

### 2.4 系统入口

在侧边栏底部提供"切换仓库"入口，点击打开此向导。

### 2.6 功能详情

#### 2.6.1 选择已有仓库

| 项目 | 说明 |
|------|------|
| 列表展示 | 显示所有已创建的仓库（名称、路径、项目数） |
| 点击选择 | 直接打开该仓库，进入系统 |
| 空状态 | 无已有仓库时，提示创建或导入 |

#### 2.6.2 创建新仓库

| 项目 | 说明 |
|------|------|
| 仓库名称 | 用户输入，默认"我的仓库" |
| 存储位置 | 用户选择，默认 `vaults/` 目录下 |
| 目录验证 | 检测目标目录是否已有仓库 |
| 创建并继续 | 创建仓库，进入步骤2初始化 |

#### 2.6.3 从备份导入

| 子步骤 | 说明 |
|--------|------|
| 选择备份 | 选择包含备份的目录（必须有 `os_compass.db` 和 `.cryptokey`） |
| 验证备份 | 检测备份文件完整性，显示验证结果 |
| 选择目标 | 选择导入到哪个目录 |
| 执行导入 | 复制备份文件到目标位置 |

#### 2.6.4 初始化仓库

| 步骤 | 说明 |
|------|------|
| 创建文件夹 | 在目标位置创建仓库目录 |
| 初始化数据库 | 创建 `os_compass.db` 和表结构 |
| 设置加密密钥 | 生成/复制 `.cryptokey` 文件 |
| 注册仓库 | 写入 last-vault.txt 和 vault-index.json |

## 9 异常处理和日志保障

### 9.1 问题背景

M15 阶段发现 AI 重新分析功能卡死 30+ 秒，根因是 JSON 解析代码块时切片范围计算错误：
```rust
// 当 find("```") 返回相对偏移 0 时
json_str = json_str[start + 7..start + end];
// = json_str[7..0] ← 无效范围！
```

**暴露的问题**：
| 问题 | 影响 |
|------|------|
| release 模式 `println!` 不输出 | 日志无法观察 |
| 切片操作无边界检查 | 程序行为未定义 |
| 错误未及时反馈 | 用户看到 loading 状态 |
| 错误类型不统一 | 前端难以处理 |

### 9.2 Task 15: 替换所有 `unwrap()` 为 `?` + 错误处理

**目标**：防止 `panic`，确保错误可恢复

**检查范围**：
```bash
# 查找所有 unwrap/expect
rg "\.(unwrap|expect)\(" --type rust
```

**修复示例**：
```rust
// ❌ 错误
let value = option.unwrap();

// ✅ 正确
let value = option.ok_or_else(|| MyError::InvalidInput("value is None".to_string()))?;
```

---

### 9.3 Task 16: 统一使用 `log` crate 替代 `println!`

**目标**：确保 release 模式日志正常输出

**修复示例**：
```rust
// ❌ 错误
println!("[DEBUG] value: {:?}", value);

// ✅ 正确
log::info!("[模块] 操作描述, value: {:?}", value);
```

**日志级别**：
| 级别 | 使用场景 |
|------|----------|
| ERROR | JSON 解析失败、数据库连接失败 |
| WARN | 配置缺失、使用默认值 |
| INFO | 函数入口、重要流程节点 |
| DEBUG | 变量值、中间状态 |

---

### 9.4 Task 17: 添加切片边界检查

**目标**：防止切片越界

**修复示例**：
```rust
// ❌ 错误
let slice = &str[start + 7..start + end];

// ✅ 正确
if end > start && end <= str.len() && start < str.len() {
    let slice = &str[start + 7..end];
} else {
    return Err(MyError::ParseError("Invalid range".to_string()));
}
```

---

### 9.5 Task 18: 统一错误类型

**目标**：统一错误类型，便于前端处理

**错误类型**：
```rust
#[derive(Debug, Error)]
pub enum AppError {
    #[error("网络错误: {0}")]
    Network(String),

    #[error("数据解析错误: {0}")]
    Parse(String),

    #[error("LLM 调用失败: {0}")]
    Llm(String),

    #[error("数据库错误: {0}")]
    Database(String),

    #[error("业务错误: {0}")]
    Business(String),

    #[error("系统错误: {0}")]
    System(String),
}
```

**错误码规范**：
| 前缀 | 类型 | 示例 |
|------|------|------|
| `NET_` | 网络错误 | `NET_TIMEOUT` |
| `PARSE_` | 解析错误 | `PARSE_JSON`, `PARSE_RANGE` |
| `LLM_` | LLM 错误 | `LLM_TIMEOUT`, `LLM_AUTH` |
| `DB_` | 数据库错误 | `DB_CONN` |
| `SYS_` | 系统错误 | `SYS_PERM` |

### 9.6 Task 19: 关键函数添加入口/出口日志

**目标**：追踪执行流程，便于问题定位

**示例**：
```rust
fn analyze_project(id: i64) -> Result<AiResult, AppError> {
    log::info!("[AI] Starting analyze_project, id={}", id);

    let result = do_analyze(id).await
        .map_err(|e| {
            log::error!("[AI] analyze_project failed: id={}, error={}", id, e);
            AppError::from(e)
        })?;

    log::info!("[AI] analyze_project complete, id={}", id);
    Ok(result)
}
```
