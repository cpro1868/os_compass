## 1. 工作包 A：首页搜索与意图搜索统一

- **里程碑归属**：M17-遗留（首页搜索统一）+ M18-遗留（首页搜索缺失能力）
- **优先级**：P0（用户已批准开发）
- **状态**：✅ 全部验收完成（2026-09-08 13:02 用户确认）
- **预估工时**：约 4h

### 1.1 背景

首页（HomePage.tsx）与意图搜索页（SearchView.tsx）并存两套搜索流程：

| 能力 | HomePage.tsx（首页） | SearchView.tsx（意图页） |
|------|---------------------|--------------------------|
| 搜索调用 | `intentSearch` 直接调用 | `intentSearch` + `analyzeIntent` 意图分析 |
| 追问澄清 | ❌ 无 | ✅ 有（clarification） |
| 搜索历史 | ❌ 无 | ✅ 有（getSearchHistory / 点击重搜） |
| 会话上下文 | ❌ 单次 | ✅ 聊天式多轮（conversationId） |
| LLM 联网结果 | ⚠️ 仅展示 llmText 文本 | ✅ 本地 + 联网结果卡片、来源标签 |
| 缓存 | ❌ 无 | ✅ 意图 + 搜索结果双缓存 |
| 仓库切换 | ❌ 无处理 | ✅ 已处理 |

### 1.2 方案（推荐）

首页保留极简入口，搜索行为与意图页完全对齐：

| # | 任务 | 内容 | 涉及文件 | 工时 |
|---|------|------|----------|------|
| A1 | 差异核对 | 逐项对照上述能力表，确认需要补齐项 | `HomePage.tsx` / `SearchView.tsx` | 0.5h |
| A2 | 首页搜索流程对齐 | 接入意图分析阶段 + 追问交互（若命中澄清）+ 历史保存 | `HomePage.tsx` / `api/search.ts` | 1.5h |
| A3 | 结果展示对齐 | 本地/联网来源标签、任务状态映射（TO_EXPLORE 等）、项目卡片复用 | `HomePage.tsx` | 1h |
| A4 | 缓存 + 仓库切换 | 复用 `intentCache`/`searchCache` 模式，切换仓库重置 | `HomePage.tsx` | 0.5h |
| A5 | 验证 | `pnpm typecheck` + `pnpm test` + `pnpm tauri build`，更新 `Previous/` | - | 0.5h |

### 1.3 验收标准

- [ ] 首页搜索与意图页返回相同结构的结果（本地 + 联网）
- [ ] 模糊意图时首页出现追问澄清交互
- [ ] 搜索完成后写入 `search_history`，历史侧栏可再点开（如首页保留侧栏）
- [ ] 仓库切换后首页搜索不残留旧仓库数据
- [ ] `pnpm tauri build` 通过，`Previous/os-compass.exe` 可用

## 3. 工作包 C：M17-遗留 向量化时机优化

- **优先级**：P2
- **状态**：⏸️ 方案待确认
- **预估工时**：约 2h

### 3.1 背景

M17 Task 6 计划在 import_project / analyze_project 末尾自动生成 embedding，但当前实现以**手动/批量按钮**（看板"向量化全部"/选中）为主，新增项目未自动向量化。

### 3.2 候选方案

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| A | 导入/爬取完成后触发 | 数据已就绪，一次到位 | 导入流程变慢、LLM 失败时无兜底 |
| B | 点击项目详情时按需生成 | 不阻塞导入，按需消耗 | 首次搜索可能无结果 |
| C | 后台队列 + 首次搜索前 | 体验平滑 | 需队列机制，复杂度最高 |

**推荐**：方案 B（改动小、不阻塞现有流程），待用户确认后补充任务拆解。
