## 1. 概述

### 1.1 目标

在项目详情中新增「项目探索」选项卡，用户通过**对话方式**与大模型交互，以当前项目的全部本地资料为知识库，对项目进行进一步深挖。

### 1.2 价值

| 痛点 | 解决方式 |
|------|----------|
| README 动辄几万字，人工通读成本高 | 直接提问，大模型基于项目资料精准回答 |
| AI 报告/Runbook 是静态产物，无法追问 | 对话式多轮追问，持续深挖 |
| 深挖得到的结论随对话流失 | 一键存入本地笔记，形成知识沉淀 |

### 1.3 定位

- **入口**：项目详情弹窗第 10 个选项卡（概览 / AI 报告 / Runbook / README / 克隆 / Releases / 本地笔记 / 用户信息 / 文章生成 / **项目探索**）
- **边界**：单项目粒度——每个项目的探索对话相互独立，仅基于当前项目资料回答，不跨项目检索

## 2. 需求确认记录（2026-10-02 与用户逐项确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 使用场景 | **通用项目问答**：不预设场景，凡是涉及当前项目的问题（架构原理、上手实操、评估决策、二次开发等）都应能回答 |
| 2 | 知识范围 | **全部项目资料**：README 原文 + AI 分析报告 + Runbook + 本地笔记 |
| 3 | 上下文策略 | **混合策略**：AI 报告/Runbook/笔记全文注入；README 分块向量化，提问时检索最相关片段注入 |
| 4 | 历史记录 | **持久化保存**：对话存入仓库库，支持多会话、历史会话列表、重开继续讨论 |
| 5 | 成果沉淀 | **支持存入笔记**：每条 AI 回答旁提供「存入笔记」按钮，一键追加到本地笔记 |
| 6 | 随行修复 | **项目详情弹窗加大加高**：当前 `max-w-7xl / max-h-[90vh]` 不够用，加入探索对话后高度更紧张，本次一并调大（2026-10-02 用户提出） |

### 安全红线（继承安全工程方法论）

- ❌ **用户信息（数据保险箱）内容绝不注入 Prompt**——Token/密码等敏感字段不得发送给 LLM
- ❌ LLM API Key 不落盘到任何文档/代码
- ✅ 探索会话数据存**仓库库**（`os_compass.db`），跟随仓库切换隔离

## 3. 功能需求

### FR-01 选项卡入口

- 项目详情弹窗新增「项目探索」选项卡，位于「文章生成」之后
- 选项卡图标：`fa-comments`（对话语义）
- i18n：zh「项目探索」/ en「Explore」

### FR-02 对话问答

- ChatGPT 风格对话界面：用户消息 + AI 消息气泡流
- AI 回答使用 MarkdownRenderer 渲染（支持加粗/列表/代码块/链接）
- 输入框：Enter 发送、Shift+Enter 换行、自动伸缩高度
- AI 生成期间显示打字指示器，生成期间禁止重复发送
- LLM 超时与错误：显示友好错误气泡 + 「重试」按钮（复用现有 180s 超时与错误分类）

### FR-03 知识库上下文组装（混合策略）

| 资料 | 注入方式 | 预算（字符） |
|------|----------|--------------|
| AI 分析报告 | 全文注入 | ≤ 3000 |
| Runbook | 全文注入（超长截断） | ≤ 6000 |
| 本地笔记 | 全文注入（超长截断） | ≤ 3000 |
| README | **分块向量检索**，注入 Top-4 相关片段 | ≤ 3200（4 × 800） |
| 对话历史 | 最近 6 轮问答 | 动态 |

- **README 分块**：按 Markdown 标题/段落切分，每块约 800 字符，块向量存入 `project_readme_chunks` 表
- **分块时机**：首次打开探索选项卡时惰性构建；README 更新（重新导入/刷新）后标记失效，下次打开时重建
- **降级策略**：向量服务（Embedding API）未配置或不可用时，自动降级为 README 头部截断注入（≤ 8000 字符），界面提示「向量检索未启用，回答可能不完整」
- **来源标注**：AI 回答卡片底部标注本轮参考的资料来源（如 `README 片段 ×2 · Runbook · AI 报告`）

### FR-04 会话管理

- 会话列表侧栏：显示当前项目全部历史会话（标题 = 首条问题截断，按最后活跃时间倒序）
- 「新建会话」按钮：开启全新对话（不复用旧上下文）
- 点击历史会话：加载完整对话记录，可继续追问（上下文延续）
- 会话删除：hover 显示 ✕，确认后删除（含全部消息）
- 关闭详情页再打开：自动恢复最近活跃会话

### FR-05 建议问题

- 欢迎消息下方提供 4 个建议问题快捷按钮：
  - 这个项目是做什么的？
  - 如何本地部署和运行？
  - 架构上有什么设计亮点？
  - 二次开发应该从哪里入手？
- 点击直接发送

### FR-06 存入笔记

- 每条 AI 回答 hover 显示操作行：「存入笔记」「复制」
- 「存入笔记」：将该条回答（Markdown 原文）追加到项目本地笔记，头部自动附加分隔线与提问摘要（`## 探索问答：<问题前 30 字>`）
- 成功后 Toast 提示；笔记内容在「本地笔记」选项卡立即可见

### FR-07 知识库状态提示

- 选项卡顶部常驻一行状态条：
  - ✅ 就绪：`知识库：README ×21 块 · AI 报告 · Runbook · 笔记 ×3`
  - ⚠️ 降级：`向量检索未启用，README 按截断注入`（附「前往设置」链接）
  - ⏳ 构建中：`正在构建知识索引...`

### FR-08 空资料兜底

- 项目无 README 且无 AI 报告时：欢迎消息中提示「当前项目资料较少，建议先返回概览页执行 AI 分析」，对话功能仍可用（大模型基于通用知识回答并明确说明）

### FR-09 项目详情弹窗尺寸调整（随行修复）

- **现状**：`ProjectDetailDialog` 弹窗为 `max-w-7xl`（约 1280px）+ `max-h-[90vh]`，内容区拥挤；加入探索对话后高度更显不足
- **调整**：
  - 宽度：`max-w-7xl` → `w-[92vw] max-w-[1600px]`
  - 高度：`max-h-[90vh]` → `h-[92vh]`（改为**固定高度**而非最大高度，保证各标签页内部布局稳定，探索对话的消息流可获得确定的 flex 空间）
- **影响面**：仅 `ProjectDetailDialog` 外层容器一行 className；各标签页内容均为流式布局，无需逐个调整
- **验收**：1280×720 与 1920×1080 两种分辨率下弹窗不溢出屏幕、各标签页无布局错位

## 4. 数据设计

### 4.1 存储位置决策

| 数据 | 存放位置 | 原因 |
|------|----------|------|
| 探索会话/消息 | **仓库库** `os_compass.db` | 按仓库隔离，切换仓库切换 |
| README 分块向量 | **仓库库** `os_compass.db` | 与 projects 数据同生命周期 |
| Embedding API 配置 | 系统库 `plugins.db`（既有） | 全局共享，复用现有配置 |

### 4.2 新增表（仓库库）

```sql
-- 探索会话
CREATE TABLE IF NOT EXISTS explore_sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  title TEXT,                      -- 首条问题截断 30 字
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 探索消息
CREATE TABLE IF NOT EXISTS explore_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL REFERENCES explore_sessions(id) ON DELETE CASCADE,
  role TEXT NOT NULL CHECK(role IN ('user','assistant')),
  content TEXT NOT NULL,
  sources TEXT,                    -- JSON: 本轮参考来源 [{"type":"readme_chunk","idx":3},...]
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_explore_messages_session ON explore_messages(session_id);

-- README 分块向量
CREATE TABLE IF NOT EXISTS project_readme_chunks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  chunk_index INTEGER NOT NULL,
  content TEXT NOT NULL,
  embedding TEXT,                  -- JSON 数组（1024 维），NULL = 未向量化
  readme_hash TEXT NOT NULL,       -- README 内容哈希，变更时整块失效
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_readme_chunks_project ON project_readme_chunks(project_id);
```

### 4.3 数据库初始化同步（M21 教训）

新增表必须同步更新 `db.rs` 两处：

| 位置 | 用途 |
|------|------|
| `INIT_SCHEMA_SQL` 常量 | 新建库时使用 |
| `missing_tables` 数组 | 已有库自动迁移 |

## 5. 技术方案（推荐：后端组装式）

### 5.1 架构

```
前端 ExplorePanel.tsx
  └─ ask(session_id, question)  ──IPC──▶  Rust explore 模块
                                            1. 确保 README 分块索引（惰性构建/失效重建）
                                            2. 问题向量化 → 余弦检索 Top-4 分块
                                            3. 组装 System Prompt（AI报告+Runbook+笔记+README片段）
                                            4. 加载最近 6 轮历史 → 调 LLM
                                            5. 写入 explore_messages → 返回回答+来源
```

- **后端新增**：`src-tauri/src/explore.rs`（上下文组装/检索/会话管理）+ `src-tauri/src/commands/explore_cmd.rs`（Tauri 命令）
- **复用既有**：`embedding.rs`（bge-m3 调用 + 余弦相似度）、`llm.rs`（OpenAI 兼容客户端、180s 超时）、`MarkdownRenderer`、SearchView 聊天交互模式
- **前端新增**：`src/components/ExplorePanel.tsx`，按 ClonePanel/ReleasesPanel 模式接入 `ProjectDetailDialog`

### 5.2 方案对比记录

| 方案 | 结论 | 原因 |
|------|------|------|
| A. 后端组装 | ✅ 采用 | 逻辑内聚可单测；避免 SearchView 曾出现的前后端逻辑脱节问题 |
| B. 前端组装 | ❌ 否决 | 上下文拼装散落 TS 难测试，与 SearchView 形成双份维护 |
| C. 纯全文注入 | ❌ 否决 | 长 README 超上下文窗口；保留为降级路径 |

### 5.3 Prompt 角色设定

System Prompt 将大模型设定为「该开源项目的资深专家」，约束：

1. 仅基于注入的项目资料回答；资料不足时明确说明「项目资料中未提及」，再补充通用知识并标注
2. 回答使用 Markdown 格式，代码示例用代码块
3. 承接多轮对话上下文，不机械重复已回答内容

## 7. 边界与异常

| 场景 | 处理 |
|------|------|
| Embedding 未配置 | 降级为 README 截断注入 + 状态条提示 + 前往设置入口 |
| LLM 未配置 | 禁用输入框，提示先配置大模型（前往设置） |
| LLM 超时/报错 | 错误气泡 + 重试按钮，不丢失用户已输入问题 |
| README 为空 | FR-08 兜底提示，对话仍可用 |
| 分块索引构建失败 | 降级截断注入，记录 warn 日志，不阻断对话 |
| 切换仓库 | 会话/分块均在仓库库，天然隔离，无需额外处理 |
| 删除项目 | 外键 CASCADE 级联删除会话/消息/分块 |
