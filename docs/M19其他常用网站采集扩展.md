### 3.3 平台识别逻辑

```rust
fn detect_platform(url: &str) -> Option<Box<dyn PlatformAdapter> {
    let url = url.to_lowercase();

    if url.contains("npmjs.com") || url.contains("registry.npmjs") {
        Some(Box::new(NpmAdapter::new()))
    } else if url.contains("pypi.org") || url.contains("pip") {
        Some(Box::new(PypiAdapter::new()))
    } else if url.contains("crates.io") || url.contains("docs.rs") {
        Some(Box::new(CratesAdapter::new()))
    } else if url.contains("hub.docker.com") || url.contains("docker.io") {
        Some(Box::new(DockerAdapter::new()))
    } else if url.contains("github.com") {
        Some(Box::new(GitHubAdapter::new()))
    } else if url.contains("gitee.com") {
        Some(Box::new(GiteeAdapter::new()))
    } else {
        None
    }
}
```

## 8. 广告学习功能（情报雷达扩展）

> **功能定位**：让用户参与广告识别，训练屏蔽模型

### 8.1 需求背景

当前情报雷达采集的数据包含广告内容，用户希望能够主动标记广告，系统自动学习广告特征并屏蔽。

### 8.2 核心流程

```
情报数据展示 → [标记广告按钮] → LLM 分析判定 → 更新屏蔽列表
                                    ↓
                           判定结果反馈用户
```

### 8.3 功能设计

#### 8.3.1 UI 交互

每条雷达数据卡片增加操作按钮：
```
[标题] [来源] [时间]
[摘要...]
─────────────────
[🔍 查看] [📋 导入] [🚫 标记广告]
```

#### 8.3.2 LLM 分析判定

当用户点击"标记广告"时：
1. 将文章标题 + 摘要发送给 LLM
2. LLM 判定是否为广告，返回结构化结果

**Prompt 示例**：
```
你是一个广告识别专家。请分析以下内容是否为广告：

标题：{title}
摘要：{summary}

请返回 JSON 格式：
{
  "is_ad": true/false,
  "confidence": 0.0-1.0,
  "ad_keywords": ["关键词1", "关键词2"],
  "ad_patterns": ["推广", "限时优惠"],
  "reasoning": "判定理由"
}
```

#### 8.3.3 屏蔽列表管理

**存储位置**：系统库（全局共享）

**数据结构**：
```sql
CREATE TABLE ad_patterns (
  id INTEGER PRIMARY KEY,
  pattern_type TEXT,      -- 'keyword' | 'domain' | 'regex'
  pattern_value TEXT,      -- 关键词/域名/正则
  confidence INTEGER,      -- 置信度 1-100
  source TEXT,             -- 'manual' | 'llm_learned'
  created_at TIMESTAMP,
  hit_count INTEGER DEFAULT 0
);
```

#### 8.3.4 屏蔽匹配逻辑

```rust
fn is_ad_content(item: &RadarItem) -> bool {
    let text = format!("{} {}", item.title, item.summary);

    for pattern in ad_patterns() {
        match pattern.pattern_type {
            "keyword" => {
                if text.to_lowercase().contains(&pattern.value.to_lowercase()) {
                    return true;
                }
            }
            "domain" => {
                if item.source_url.contains(&pattern.value) {
                    return true;
                }
            }
            "regex" => {
                if Regex::new(&pattern.value).is_match(&text) {
                    return true;
                }
            }
        }
    }
    false
}
```

## 10. 情报雷达定时采集功能

> **功能定位**：情报雷达定时自动采集，有新内容时通知用户
>
> **原型文件**：`design-system/public/radar-inbox.html`

### 10.1 需求背景

当前情报雷达需要手动触发采集，用户希望开启后系统自动定时采集，新内容通过系统通知提醒。

### 10.2 采集模式

| 模式 | 说明 | 示例 |
|------|------|------|
| 间隔模式 | 固定时间间隔 | 5分钟/15分钟/30分钟/1小时/2小时/6小时/12小时/24小时 |
| 自定义模式 | 秒/分/时自定义 | 每30秒、每5分钟、每1小时 |

### 10.3 核心流程

```
用户开启定时采集 → 系统后台运行 → 定时触发采集 → 比对去重 → 有新内容 → 系统通知 + 雷达图标徽章
                                                                              ↓
                                                                        更新雷达列表
```

### 10.4 功能设计

#### 10.4.1 顶部栏布局

```
[Logo] 情报雷达 | 时间筛选 | 清空 | ⏰ 自动采集(OFF) | ⚙️ | 立即扫描 | 隐藏信息源
```

**定时采集开关**：
- 显示 OFF/ON 状态
- 点击开关直接切换
- 开启后显示当前间隔（如"每15分钟"）
- 旁边设置按钮打开配置弹窗

#### 10.4.2 配置弹窗

**采集模式**：
- 间隔模式：下拉选择固定间隔
- 自定义模式：秒/分/时三级选择 + 数值输入

**通知设置**：
- 启用通知（总开关）
- 系统通知
- 雷达图标徽章（显示未读数）

**运行状态**：
- 当前状态（运行中/已停止）
- 下次采集时间

#### 10.4.3 后台运行机制

**Tauri 后台任务**：
```rust
#[tauri::command]
async fn start_scheduled_radar(app: AppHandle) {
    let config = get_radar_schedule_config();
    let interval = calculate_interval_seconds(&config);
    loop {
        tokio::time::sleep(Duration::from_secs(interval)).await;
        if config.enabled {
            let new_count = run_radar_collection().await;
            if new_count > 0 {
                show_notification(new_count);
                update_badge(new_count);
            }
        }
    }
}
```

**采集间隔计算**：
- 间隔模式：`interval_seconds`
- 自定义模式：`custom_value × unit_seconds`

**托盘图标状态**：

| 有新内容 | 📢 | 情报雷达 - 有新消息 |
