## 1. 项目背景与研发初衷 (Project Background)

随着全球开源生态的爆炸式增长，开发者几乎每天都会接触到各种前沿的开源库、框架和工具。然而，在海量开源红利背后，开发者和企业技术团队正面临着三大核心痛点：

1. **“收藏即吃灰”的资产管理困境：** 传统的浏览器书签或单纯的 GitHub Star 功能极为单薄。开发者收藏了大量项目，但由于缺乏体系化的分类、结构化的描述和状态追踪，这些资产最终沦为一团乱麻的“数据坟场”，在真正需要技术选型时往往无从找起。
   
2. **极高的“上手与验证”成本：** 跑通一个陌生的开源项目往往令人头疼。开发者需要面对语言各异（如全英文、俄文或日文）、极其冗长且重点模糊的 README 文档，还要解决复杂的本地环境依赖冲突。许多优秀的开源项目因此将新手拒之门外。
   
3. **“带着业务找轮子”的检索鸿沟：** 当开发者面临具体的业务需求（例如：“如何快速在本地部署一个能离线批量处理图片水印的工具”）时，传统的关键字搜索效率极低，难以在全网快速匹配并横向对比出最合适的开源解决方案。
   

**OS-Compass (开源罗盘)** 正是在此背景下应运而生。它不是一个简单的网址导航或书签管理器，而是**一款为开发者量身定制的“AI 开源资产智能管家”**。它通过大语言模型（LLM）的阅读理解和归纳能力，代替人工去“啃”那些难懂的文档；通过多层级本地分类树，帮开发者建立清晰的技术知识图谱；通过打通本地工作区，让代码的下载与部署变得触手可及。最终，帮助开发者将浩如烟海的“开源信息”，真正转化为受自己掌控的“本地核心资产”。

## 2. 产品定位与战略设定

### 2.1 产品定义

**OS-Compass (开源罗盘)** 是一款基于“本地优先 (Local-First)”理念设计的桌面端开源项目全生命周期管理与决策系统。通过 AI 大模型和本地数据链路的深度结合，解决开发者在开源项目搜集、评估、翻译、本地部署及二次开发过程中的摩擦力，打造极致的开源知识资产管理闭环。

### 2.2 核心技术底座

- **客户端框架:** Tauri (Rust + Webview)，保障极低内存占用与系统级 API 权限（用于本地 Git 下载与文件管理）。
  
- **本地存储引擎:** SQLite 3 (搭配 `sqlite-vss`) + 本地文件系统 (存储克隆的源码)。
  

## 3. 核心业务模块详解 (Core Modules)

### 3.1 独立分类管理模块 (Category Taxonomy)

分类不应仅仅是简单的标签，而是系统自动归类的“导航图”。系统提供独立的分类管理面板。

- **树形结构管理:** 支持无限极父子层级树状结构，支持拖拽调整层级关系与排序。
  
- **分类属性定义:** 每个分类节点包含：
  
    - `分类名称` (如：大语言模型推理框架)
      
    - `层级关系` (如：AI/底层框架/推理框架)
      
    - `分类描述` **(关键创新)**：支持用户手动输入一段描述，如“用于本地运行或加速大模型推理的 C++ 或 Python 框架，包含 llama.cpp 等”。**该描述将作为上下文注入给 LLM，极大提升 LLM 自动入库时的路由归类准确率。**
      

### 3.2 开源项目资产展示与检索 (Views & Query)

为了满足不同场景下的查找需求，首页支持两种无缝切换的视图模式：

- **列表+高级查询模式 (List & Query View):** * 传统紧凑型数据表格结构。展示字段：项目名称、分类、Star 数，语言、健康度、最近更新。

    - 顶部提供组合筛选器：支持通过关键字（全文检索）、树状分类下拉框、多标签交集、更新时间范围进行精准定向检索。

    - **批量操作支持**：复选框多选，支持批量移动分类、批量归档、批量导出 JSON/CSV。

- **看板模式 (Kanban View):** * 以"项目生命周期状态"为列（`💡 待探索` -> `🔬 研究中` -> `✅ 已落地` -> `🗑️ 归档`）。

    - 核心诉求是**快速定位和状态流转**，支持鼠标拖拽卡片在不同状态间流转。

    - **归档理念**：删除改为归档（软删除），避免误操作导致数据丢失。归档后可恢复或永久删除。
      

### 3.3 项目详情与 LLM 深度体检报告 (Details & Evaluation)

当用户点击进入项目详情页时，展示 LLM 经过深度分析、精简与翻译后的综合报告。

#### 3.3.1 智能翻译与本地化展示

- **非默认语言处理:** 系统通过检测 README 或主要文档的语言属性。若判定为外语，将触发 **自动翻译机制**（根据[系统设置]中的“默认目标语言”设定，如自动翻译为中文）。
  
- **双语对照选项:** 在详情页顶部提供 `原文 / 翻译版` 切换 Toggle，确保专业术语的准确性溯源。
  

#### 3.3.2 深度评估与指导报告 (AI Evaluation Report)

LLM 需通过分析项目的源码结构、README、最近的 Issues 及评论区情绪（Sentiment Analysis），生成以下核心板块：

1. **现状与健康度体检:** * 团队状态（维护者是否活跃、Issue 处理周期）。
   
    - 安全漏洞预警（基于历史 Issue 与依赖库评估潜在安全风险）。
      
    - 用户口碑分析（从评论和讨论区提取优点与致命缺陷）。
    
2. **场景化指导手册 (AI Runbook):**
   
    - **运行/使用:** 精简翻译后的前置环境要求与一键复制启动命令。
      
    - **部署/发布:** 生产环境下的环境变量配置建议与合规性（License）打包指引。
      
    - **二次开发:** 源码核心目录地图（指出核心逻辑所在路径），以及支持的 API/插件扩展方式。
      

### 3.4 代码下载与本地联动 (Download & Local Workspace)

系统直接打通本地开发环境，不再仅限于“看”。

- **一键本地克隆:** 详情页提供 `[下载到本地]` 按钮。
  
- **执行逻辑:** * 系统读取 [全局设置] 中的“默认本地源码存放目录”（如 `D:/OpenSource_Workspace`）。
  
    - 结合 [全局设置] 中的“代理 (Proxy) 配置”，通过 Tauri 底层调用系统 Git 进程执行 `git clone`。
    
- **状态追踪:** 下载完成后，详情页状态更新为 `[打开本地目录]` / `[使用 VS Code 打开]`，实现一站式研发直达。
  

### 3.5 意图驱动网络搜索与推荐 (Intent-based Search)

- **业务诉求检索:** 用户输入纯业务需求（如：“怎么批量去图片水印”）。
  
- **RAG 联网检索:** LLM 解构需求，全网搜索开源方案，输出包含“匹配度、技术原理、风险”的对比矩阵，并支持一键将结果同步入库（自动挂载分类）。
  

### 3.6 情报雷达与个人化推送 (Radar Feed)

- **被动情报源:** 定时通过 RSS、Telegram 等渠道抓取最新开源资讯。

- **情报收件箱:** 支持对已采集数据进行搜索增强展示：
  - 关键字搜索：模糊匹配项目名称和描述
  - 信息源筛选：按来源信息源多选筛选
  - 时间范围筛选：按数据采集时间精确筛选（开始日期 ~ 结束日期）
  - 分页浏览：支持每页显示数量配置（10/20/50条），完整分页导航

- **广告过滤插件:** 采集时自动过滤广告和垃圾信息：
  - 基于 banlex 词库检测（spam/scam/harassment 分类）
  - 支持中文扩展词库（针对 Telegram 和国内平台优化）
  - 强度控制：关闭/低/中/高四级可调
  - 混淆检测：支持 leetspeak、零宽字符等混淆手段

- **个性化分发:** 结合用户的搜索历史和已有的本地分类权重，进行精准推荐。支持在"情报收件箱"中点选"感兴趣（入库）"或"不感兴趣（入黑名单）"。

## 4. 全局系统设置中心 (System Settings)

系统必须提供一个统一的设置中心（Settings），用以支撑上述复杂业务的运转。核心设置项分为四大类：

### 4.1 网络与代理设置 (Network & Proxy) - 分层架构

系统采用**分层代理架构**，不同功能使用独立的代理配置：

| 代理类型 | 配置位置 | 用途范围 |
|---------|---------|---------|
| **下载代理** | 系统设置 → 下载页 | Git Clone、爬虫服务 |
| **LLM 代理** | 系统设置 → 大模型页 | LLM API 调用 |
| **扩展代理** | 各扩展配置页 | 各扩展独立使用 |

**下载代理配置**（用于代码下载、爬虫服务）：
- `全局代理开关 (Toggle)`
- `代理协议 (Protocol)`: HTTP / HTTPS / SOCKS5
- `代理地址与端口 (Proxy URL & Port)`: 如 `127.0.0.1:7890`
- `身份验证 (Authentication)`: Proxy Username / Proxy Password (可选)

**LLM 代理配置**（用于 AI 分析、翻译等 LLM 调用）：
- `LLM 代理开关 (Toggle)`
- `代理协议 (Protocol)`: HTTP / HTTPS / SOCKS5
- `代理地址与端口`
- `身份验证`（可选）

### 4.2 大模型集成设置 (LLM Configuration)

- `LLM 供应商选择`: OpenAI / Anthropic / 深度求索 / 本地 Ollama 等。
  
- `API Base URL` (支持反代地址)
  
- `API Key` (本地安全加密存储)
  
- `使用的核心模型 (Model Name)` (如 `gpt-4o`, `deepseek-chat`)
  

### 4.3 本地化与翻译偏好 (Localization & Translation)

- `系统 UI 语言`: 简体中文（默认）/ English

    - 使用 i18n 框架实现，界面文本与业务数据分离，切换后立即生效。

- `阅读默认目标语言`: 如设定为"简体中文"。

- `开启自动翻译开关`: 开启后，所有抓取的非目标语言 README 都将经过 LLM 翻译后落库。
  

### 4.4 存储与工作区偏好 (Storage & Workspace)

- `数据库存储位置`: 设定 `.db` 文件的存放盘符。
  
- `默认源码下载目录`: 设定 `git clone` 存放的根文件夹路径。
  
- `默认代码编辑器`: 如下载完成后默认使用 `VS Code` 或 `Cursor` 打开。

### 4.5 仓库管理模块 (Vault Management)

借鉴 Obsidian 的 Vault 概念，将数据存储抽象为独立的「仓库（Vault）」单元，支持多仓库管理。

#### 4.5.1 核心概念

- **仓库 (Vault)**：独立的数据存储单元，包含完整的项目数据、设置、笔记等
- **仓库索引 (Vault Index)**：主索引文件，记录所有已注册的仓库路径
- **当前仓库 (Current Vault)**：应用启动时打开的仓库，记录在本地配置

#### 4.5.2 功能需求

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 创建仓库 | 指定名称和目录，创建新的 SQLite 数据库并执行初始化脚本 | P0 |
| 导入已有仓库 | 选择已有仓库文件目录，校验齐全、有效后登记回仓库清单（不立即切换） | P1 |
| 仓库列表 | 显示所有仓库，显示名称、路径、项目数量、最后访问时间 | P0 |
| 切换仓库 | 选择已有仓库，验证数据库有效性后切换 | P0 |
| 删除仓库 | 支持仅移除索引（保留文件）或彻底删除数据库文件 | P1 |
| 打开仓库文件夹 | 在文件管理器中打开仓库所在目录 | P2 |

#### 4.5.3 创建仓库流程

创建新仓库时，应显示实时进度和状态：

1. **验证目录有效性** - 检查目录是否存在或可创建
2. **创建数据库文件** - 在指定目录下创建 SQLite 数据库文件
3. **执行初始化脚本** - 创建所有必需的表结构、索引等
4. **验证数据库结构** - 确保数据库可用

每个步骤应显示执行状态（待处理/进行中/成功/失败），失败时提供错误信息。

#### 4.5.4 仓库文件结构

```
/data/
├── vault-index.json          # 主索引：记录所有仓库
├── last-vault.txt            # 当前仓库路径
└── /vaults/
    ├── work/
    │   ├── config.json       # 仓库元数据
    │   └── os_compass.db     # SQLite 数据库
    └── personal/
        ├── config.json
        └── os_compass.db
```

#### 4.5.5 vault-index.json 结构

```json
{
  "version": "1.0",
  "vaults": [
    {
      "id": "uuid",
      "name": "工作项目库",
      "path": "D:/data/vaults/work",
      "created_at": "2026-07-08T10:00:00Z",
      "last_opened": "2026-07-08T14:30:00Z"
    }
  ]
}
```

#### 4.5.6 UI 入口

- 设置中心新增「仓库管理」标签页
- 或作为独立菜单入口

#### 4.5.7 仓库验证规则

切换仓库时需验证：
- 数据库文件存在
- 可正常打开连接
- 表结构完整（检查关键表是否存在）

验证失败时提示具体原因，不允许切换。

#### 4.5.8 导入已有仓库

**适用场景**：用户手上有完整的仓库文件但仓库不在清单里（重装系统、换电脑后从备份恢复、`vault-index.json` 丢失、手动复制仓库目录到另一台机器等）。

**操作流程**：
1. 在仓库管理弹窗点击"导入已有仓库"卡片
2. 选择含仓库文件的目录（必须含 `os_compass.db` 和 `.cryptokey`）
3. 仓库名默认取目录名，可手动修改
4. 点击"验证并导入"，后端按顺序校验：
   - 目录存在
   - `os_compass.db` 存在
   - `.cryptokey` 存在
   - db 能打开（合法 SQLite 文件）
   - 12 张必需表全在
   - 关键列存在（`tags.source`、`projects.data_status`、`projects.lifecycle_status`、`system_variables.is_secret`）
   - 密钥匹配验证（仅当 db 中有加密数据时，用 `.cryptokey` 解密一条记录验证密钥正确）
   - 路径不在 `vault-index.json` 里（重复导入以无效论处）
   - 名称不与现有清单重复
5. 校验通过 → 写入 `vault-index.json`，刷新列表，**不切换**到该仓库
6. 校验失败 → 在弹窗内显示具体错误，用户可改名称或重选目录后重试

**约束**：
- 不做自动扫描批量导入（用户手动选目录）
- 不做 schema 自动迁移（旧版本直接拒绝）
- 不跑 `PRAGMA integrity_check`
- 导入是只读操作，不修改目标目录里的任何文件
- 不在导入时重建 `config.json`

## 5. 本地 SQLite 数据库结构增强设计

为支撑 V1.0.2 版本的新增逻辑，本地 `metadata.db` 结构进一步重构：

### 5.1 categories (分类目录表 - 新增描述字段)

|字段名|数据类型|说明|
|---|---|---|
|`id`|INTEGER|分类自增 ID|
|`name`|VARCHAR(100)|分类名称|
|`parent_id`|INTEGER|父级分类 ID，构建树形结构|

### 5.2 projects (开源项目主表 - 补充下载与语言状态)

|字段名|数据类型|说明|
|---|---|---|

|`category_id`|INTEGER|关联的 categories ID|
|`name`|VARCHAR(255)|项目名称|
|`repo_url`|TEXT|仓库网址|
|`status`|VARCHAR(50)|生命周期状态：探索、研究、落地、弃用|
|`source_language`|VARCHAR(20)|**原始语言（如 en, ja），用于判定是否需要翻译**|
|`is_translated`|BOOLEAN|**是否已包含翻译版本的评估报告**|

### 5.3 配置文件结构 (`config.json`)

系统的 Proxy、LLM Key、下载路径等全局系统设置中心的数据，不存入跨设备可能冲突的 SQLite，而是以本地 `config.json` 进行持久化存储。

## 3.7 用户自定义信息管理区（数据保险箱）

每个项目详情页内嵌独立的用户信息管理区，用于存储与项目相关的敏感凭证。

- **字典管理**：键值对形式，支持存储用户名、密码、API Token、配置项等
- **安全存储**：敏感信息（如密码/Token）使用 AES-256-GCM 加密后存储
- **加密密钥**：首次启动时自动生成，存入 OS 密钥库（Windows Credential Manager / macOS Keychain），用户无感
- **快捷操作**：点击复制按钮将值复制到剪贴板
- **导入/导出接口**：二期实现

### 3.8 安全设计

| 数据类型 | 存储位置 | 保护方式 |
|----------|----------|----------|
| 数据库地址 | `config.json` | 明文 |
| 系统配置（代理、LLM Base URL 等） | SQLite | 明文 |
| 项目信息（名称、URL、分类、AI 报告、笔记） | SQLite | 明文 |
| **用户字典（密码、Token 等敏感字段）** | SQLite | **AES-256-GCM 加密** |
| 应用加密密钥 | OS 密钥库 | 系统级保护 |

## 7. 非功能性需求

### 7.1 性能基线

- **性能基线:** 后台雷达静默占用 CPU < 5%，常驻内存 < 50MB。多视图切换及列表检索（10000条级别数据）无卡顿。

### 7.2 本地优先与离线支持

- **本地优先 (Local-First)**: 项目数据存储在本地 SQLite，无网络时仍可浏览已导入项目。

- **离线场景**: 已生成的分析报告、AI 摘要、翻译内容均可离线查看。

- **网络容错**: 网络不稳定时保存已获取数据，标记状态并提供重试机制。

### 7.3 统计面板

- 提供项目库可视化统计，包括：
  - 健康度分布饼图
  - 分类分布柱状图
  - 编程语言分布
  - 标签使用排行
- 入口：设置中心提供链接

### 7.4 隐私安全

- **隐私安全:** 严禁客户端未经许可向第三方云端上传任何用户 API Key、代理账户及本地工作区路径信息。
