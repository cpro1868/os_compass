## 教训与反思

### 1. 阶段区分

| 阶段 | 可操作内容 | 禁止操作 |
|------|-----------|----------|
| **需求讨论** | 口头讨论、文档记录 | 代码、编译、构建 |
| **原型设计** | HTML 原型、交互设计 | 代码、编译、构建 |
| **设计确认** | 确认设计文档 | 代码、编译、构建 |
| **开发实施** | 代码、编译、构建 | - |

### 2. 操作纪律

- 用户未明确说"可以开发"时，**禁止修改任何代码文件**
- 设计/原型相关文件（`.html`）可在设计阶段修改
- `src/` 目录下所有文件（包括 `.tsx`, `.ts`, `.rs`）在设计阶段禁止修改

### 3. 回退检查清单

回退代码后必须验证：
- [ ] `src/components/` 下无新增未完成组件
- [ ] `src/App.tsx` 未被修改
- [ ] `Previous/` 目录使用干净版本重新构建
- [ ] 用户测试确认功能正常

## 附录：系统库与仓库库规范

### 正确路径定义

| 类型 | 获取 API | 作用 |
|------|----------|------|
| **系统库** | `BaseDirs.data_dir().join(".os-compass")` | 全局共享数据（插件、雷达、系统设置） |
| **仓库库** | `app.path().app_data_dir().join("vaults")` | 项目私有数据（项目、分类、标签、笔记、用户信息） |

### 加密区分

| 类型 | 密钥位置 | 说明 |
|------|----------|------|
| **系统库** | 系统目录内 | 系统级加密密钥 |
| **仓库库** | 仓库目录 `.cryptokey` | 每个仓库独立密钥 |

### 区分原则

1. **API 区分**：系统库用 `BaseDirs`，仓库库用 `app.path().app_data_dir()`
2. **路径区分**：两个库不能放在同一个父目录下
3. **加密区分**：两个库使用不同的加密方式
4. **迁移性**：系统库不可迁移，仓库库可随仓库迁移
