# 事件记录：V2.0 扩展配置丢失 Bug

## 事件概述

| 项目 | 内容 |
|------|------|
| 日期 | 2026-07-14 |
| 严重性 | **P0 - 功能阻断** |
| 影响范围 | 扩展配置（source_plugins）丢失，无法从 GitHub/Gitee 采集项目 |
| 持续时间 | 数小时 |

## 问题描述

1. **LLM 配置保存后重启丢失**
2. **扩展配置（source_plugins）被清空**，设置页面显示空白
3. **用户无法配置 GitHub/Gitee Token**

## 根因分析

| 问题点 | 说明 |
|--------|------|
| **需求理解不足** | V2.0 架构中，`source_plugins` 表的 `url_patterns` 字段是核心需求（M13 情报雷达链接高亮功能），但代码和 SQL 脚本不一致 |
| **整体思维缺失** | 只修改了 `db.rs` 中的内嵌 SQL，没同步修改 `scripts/init_schema.sql` 外部脚本 |
| **测试缺失** | 没有验证数据库初始化脚本是否正确执行，导致问题泄露给用户 |

### 技术根因

```sql
-- db.rs 内嵌 SQL（正确）
CREATE TABLE source_plugins (
    url_patterns TEXT,  -- 有这个字段
    ...
);

-- scripts/init_schema.sql（缺失）
CREATE TABLE source_plugins (
    -- 没有 url_patterns 字段！
    ...
);
```

## 改进措施

### 1. 代码与脚本同步机制

**问题**：外部脚本 `scripts/init_schema.sql` 与内嵌 SQL 不一致

**改进**：
- 每次修改 `db.rs` 中的 `INIT_SCHEMA_SQL`，必须同步修改 `scripts/init_schema.sql`
- 创建 CI 检查脚本，验证两个文件的一致性

### 2. 数据库初始化验证

**问题**：没有验证数据库初始化是否正确执行

**改进**：
- 添加启动日志：`[db] Initializing schema from external script` / `from embedded SQL`
- 添加数据库完整性检查命令
- 前端添加数据库状态检查（表是否存在、数据条数）

### 3. 发布前测试清单

**问题**：发布前没有进行基本功能测试

**改进**：
- 每次发布前必须执行：
  1. 删除旧数据库文件
  2. 启动程序
  3. 验证扩展配置页面显示 GitHub/Gitee/Crawler
  4. 验证系统变量页面显示 github_token/gitee_token/github_proxy
  5. 验证 LLM 配置保存后重启不丢失

### 4. 文档更新

**问题**：开发计划没有明确要求测试数据库初始化

**改进**：
- 在 `docs/开发前检查清单.md` 中添加数据库初始化测试项
- 在 `docs/M13实施计划.md` 的 Self-Review Checklist 中添加数据库验证项

## 教训总结

1. **整体思维**：V2.0 架构涉及多个层面（数据库、配置迁移、前端），必须完整考虑
2. **测试前置**：任何影响数据持久化的改动，都必须手动测试
3. **用户第一**：发布的程序必须经过基本功能验证，不能将测试丢给用户
