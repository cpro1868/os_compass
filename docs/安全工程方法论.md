## 1. 安全目标
- 保护用户敏感信息不被泄露
- 防止 API Key、密码等凭据写入文件或日志
- 确保本地数据库文件即使被拷贝也无法直接读取敏感内容

## 2. 威胁模型
- 恶意软件窃取本地数据库文件
- 用户误将包含敏感信息的配置文件提交到 Git
- 日志文件泄露 API Key

## 3. 安全设计原则

### 3.1 最小权限
- 应用仅请求必要的 OS 权限
- 数据库文件权限设置为仅当前用户可读写

### 3.2 纵深防御
- 敏感数据多层保护：OS 密钥库 + 应用主密钥 + 字段级加密
- 日志脱敏：禁止打印完整 Token、密码

### 3.3 默认安全
- 默认启用加密
- 默认不存储明文敏感信息

## 4. 密钥管理

### 4.1 应用主密钥
- 生成：应用首次启动时生成 256-bit 随机密钥
- 存储：OS 密钥库（Windows Credential Manager / macOS Keychain / Linux libsecret）
- 用途：派生 AES-256-GCM 密钥，加密用户自定义敏感字段

### 4.2 LLM API Key
- 存储：直接存入 OS 密钥库
- 使用：运行时读取，仅用于 HTTP 请求
- 禁止：写入任何配置文件、数据库、日志

## 5. 数据加密

### 5.1 算法
- 对称加密：AES-256-GCM
- 密钥派生：HKDF-SHA256
- 随机数：每次加密生成新的 96-bit nonce

### 5.2 加密范围
- 用户自定义信息管理区中的敏感字段
- 本地笔记中标记为"加密"的内容

### 5.3 不加密范围
- 项目公开元数据（名称、URL、描述）
- 分类树
- AI 生成的公开报告

## 6. 安全开发规范

### 6.1 代码规范
- 禁止在代码中硬编码任何密钥、Token
- 禁止将完整凭据打印到日志
- 禁止将 `.env`、数据库、配置文件提交到 Git
- 敏感配置使用 `config.example.json` 模板

### 6.2 代码审查清单
- 新增代码是否涉及敏感信息处理？
- 是否有打印日志可能泄露敏感信息？
- 是否有新的文件读写需要设置权限？

## 7. Rust 加密示例

```rust
use aes_gcm::{Aes256Gcm, KeyInit, Nonce};
use aes_gcm::aead::Aead;

fn encrypt(plaintext: &[u8], key: &[u8; 32], nonce: &[u8; 12]) -> Vec<u8> {
    let cipher = Aes256Gcm::new_from_slice(key).unwrap();
    cipher.encrypt(Nonce::from_slice(nonce), plaintext).unwrap()
}
```

## 8. 凭据迁移安全规范

### 8.1 背景
多仓库架构下，新建仓库时 `app_settings` 表为空会触发 legacy migration（从旧 `settings.db` 或 `config.json` 读取配置）。如果迁移逻辑包含凭据类字段，会导致**每个新建仓库都继承老仓库的 LLM API Key、Proxy 凭据等敏感信息**，造成跨仓库凭据泄露。

### 8.2 迁移字段分类

| 分类 | 字段 | 允许迁移 |
|------|------|----------|
| **用户偏好（安全）** | theme、default_language、auto_translate_readme、auto_translate_report、download_path、default_editor、crawler_enabled、readme_update_frequency、translate_engine | ✅ |
| **LLM 连接凭据** | llm_provider、llm_api_base、llm_api_key、llm_model | ❌ 禁止 |
| **LLM 代理凭据** | llm_proxy_enabled、llm_proxy_protocol、llm_proxy_host、llm_proxy_port、llm_proxy_username、llm_proxy_password | ❌ 禁止 |
| **下载代理凭据** | proxy_enabled、proxy_protocol、proxy_host、proxy_port、proxy_username、proxy_password | ❌ 禁止 |
| **Google 翻译凭据** | google_api_key、google_proxy_enabled、google_proxy_protocol、google_proxy_host、google_proxy_port、google_proxy_username、google_proxy_password | ❌ 禁止 |
| **爬虫服务地址** | crawler_api_url | ❌ 禁止（可能含认证信息） |

### 8.3 迁移规则
- 新建仓库的凭据类字段一律保持空白，由用户按需重新配置
- `apply_legacy_settings()` 函数只迁移用户偏好类字段
- 禁止在 `Default` trait 实现中硬编码任何代理地址、端口、API 地址作为默认值（空字符串和 0 端口除外）
- 禁止在 SQL 初始化脚本的描述字段中写入具体的代理地址示例（如 `http://127.0.0.1:7890`）

### 8.4 导入已有仓库的凭据安全
- 导入仓库时校验 `.cryptokey` 与数据库加密数据匹配，防止密钥不匹配导致凭据无法解密
- 导入是只读操作，不修改目标目录里的任何文件
- 导入后不立即切换仓库，用户需手动切换

## 9. 仓库初始化安全规范

### 9.1 新建仓库
- 每个仓库生成独立的 AES-256-GCM 密钥，存放在仓库目录下的 `.cryptokey` 文件
- 密钥文件不提交到 Git
- 新建仓库的 `app_settings` 表只包含用户偏好默认值，不含任何凭据

### 9.2 初始化脚本（init_schema.sql）
- `system_variables` 表的 seed 数据中，凭据类变量（github_token、gitee_token）初始值为空字符串
- `source_plugins` 表的 `required_variables` 描述字段中禁止包含具体的代理地址、端口示例
- 脚本可放在 exe 同级 `scripts/` 目录供用户维护，也可内嵌在二进制中作为兜底

### 9.3 代码默认值
- `AppSettings::default()` 中所有凭据类字段必须为空字符串或 0
- `get_settings()` 回退值同样必须为空字符串或 0
- 禁止将用户真实配置（如特定代理端口 `8964`）作为代码默认值
