## 1. 现状勘察（设计依据，均已核实源码）

### 1.1 `categories` 表真实结构（`db.rs` INIT_SCHEMA_SQL）

```sql
CREATE TABLE IF NOT EXISTS categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    parent_id INTEGER REFERENCES categories(id),
    sort_order INTEGER DEFAULT 0,
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

**⚠️ 关键结论：表结构没有 `explain`、`path`、`is_system` 列。**

| 字段 | 表内 | 备注 |
|------|------|------|
| `explain` | ❌ 无 | `Category` 模型有该字段（`models/mod.rs:70`），但**从未持久化**，`get_categories` 恒返回 `None` |
| `path` | ❌ 无 | 运行时由 `format!("/{name}")` 现场构造（`project.rs:259`） |
| `is_system` | ❌ 无 | 运行时判断 `id == 1`（`project.rs:263`） |

> **设计影响**：原 v1 稿中"JSON 支持 explain 字段"**无法落地**。详见 §3.2 与 §11。

### 1.2 生效的分类命令（`commands/project.rs`，已注册）

| 命令 | 行号 | 说明 |
|------|------|------|
| `get_categories()` | 246 | 查 6 列，现场构造 `path/explain/is_system` |
| `get_category(id)` | 523 | 同上，单条 |
| `create_category(input: serde_json::Value)` | 549 | 仅写 `name/parent_id/sort_order` + 时间戳 |
| `update_category(input: Category)` | 565 | 仅更新 `name/parent_id/sort_order` |
| `delete_category(id)` | 578 | 硬删除（未做级联处理） |

> `commands/category.rs` 是**未接入死代码**（`commands/mod.rs` 未声明，不参与编译），新功能**不得**放在其中。

### 1.3 可复用的现有逻辑（`db.rs:417`）

```rust
pub fn import_preset_categories_into(conn: &rusqlite::Connection, txt: &str) -> Result<i64, String>
```

已实现：按 `/` 拆路径 → 逐级 `SELECT id FROM categories WHERE name=?1 AND parent_id IS ?2` 判存在 → 不存在则 `INSERT ... sort_order=0` → 动态自增 id → 幂等。

**本功能直接复用该函数，但需扩展以支持：**
1. 可选 `parent_id`（导入到指定父分类下，而非固定顶级）
2. JSON 解析为路径条目后同样走此逻辑
3. 解析错误收集（返回 `errors` 列表，不中断）

### 1.4 前端现状（`components/CategoryManager.tsx`）

- 头部右侧只有一个"新增"按钮（`openNew(null)`）
- 树构建：`buildTree` 按 `parent_id` 递归
- 表单含 `explain` 输入框但**保存后不生效**（后端不存）——属于既有缺陷，本次**不在范围内**修复，但会阻止新建 UI 暴露 explain 给导入
- 弹窗风格：`bg-gray-50 dark:bg-gray-900` 卡片 + Tailwind

## 3. 文件格式规范

### 3.1 TXT 路径格式 `.txt`

```
# 注释行：以 # 开头整行跳过（也兼容 -- 前缀，与预设脚本一致）
技术/前端开发/Web框架/React生态
技术/前端开发/Web框架/Vue生态
技术/AI与机器学习/大模型与LLM

商业/金融科技/支付系统
```

**语法规则**（与现有 `import_preset_categories_into` 完全一致）：
- 一行一条，`/` 分隔层级
- 每段 `trim()` 后不能为空（空段丢弃，行全空则跳过）
- 空行、`#` 开头、`--` 开头跳过
- 段内不允许再含 `/`（即不允许转义）

### 3.2 JSON 格式 `.json`

```json
[
  { "path": ["技术", "前端开发", "Web框架"], "name": "React生态" },
  { "path": ["技术", "AI与机器学习"], "name": "大模型与LLM" },
  { "name": "杂项" }
]
```

**语法规则**：
- 顶层必须是 JSON 数组
- `path`：可选，数组，表示该分类的**父级路径**（不含自身 name）
- `name`：必填，字符串，该分类名
- `explain`：**可选，v1 解析后忽略**（表无该列，见 §11 风险）
- 未知字段：忽略
- `path` 缺省或为空数组 = 顶级分类

> **为何忽略 explain 而非报错**：若报错会把合法的数据拒之门外；忽略则数据仍可导入，功能不依赖 explain。

### 3.3 内部统一表示（两种格式归一化）

```rust
pub struct CategoryItem {
    /// 完整层级路径（含自身 name），如 ["技术","前端开发","Web框架","React生态"]
    pub full_path: Vec<String>,
    /// 原始来源（行号，用于错误提示），1-based
    pub source_line: usize,
}
```

解析器统一输出 `Vec<CategoryItem>`，后续判重/导入与格式无关。

## 5. 后端详细设计

### 5.1 新命令（注册到 `commands/project.rs`，并在 `lib.rs` 的 `invoke_handler` 注册）

```rust
/// 解析分类文件并返回预览（不写数据库）
#[tauri::command]
pub fn parse_categories_file(
    file_path: String,
    parent_id: Option<i64>,   // 预览时用于判重（导入到该分类下）
) -> Result<ParsedCategories, String>
```

```rust
/// 导入分类文件（后端重读文件，事务写入）
#[tauri::command]
pub fn import_categories_from_file(
    file_path: String,
    parent_id: Option<i64>,   // None = 顶级；Some(id) = 挂到该分类下
) -> Result<ImportSummary, String>
```

### 5.2 数据结构

```rust
#[derive(Debug, Serialize, Clone)]
pub struct ParsedCategories {
    pub total: u32,               // 有效条目总数
    pub items: Vec<PreviewItem>,  // 预览明细
}

#[derive(Debug, Serialize, Clone)]
pub struct PreviewItem {
    pub full_path: String,     // "技术/前端开发/Web框架/React生态"
    pub status: String,        // "new" | "skip" | "error"
    pub reason: Option<String>,// error 时的原因
    pub source_line: usize,    // 原始行号（txt）或数组索引+1（json）
}

#[derive(Debug, Serialize)]
pub struct ImportSummary {
    pub created: u32,      // 实际新增分类数（含中间父级）
    pub skipped: u32,      // 跳过的条目数（已存在）
    pub errors: Vec<ImportError>,
}

#[derive(Debug, Serialize)]
pub struct ImportError {
    pub source_line: usize,
    pub full_path: String,
    pub reason: String,
}
```

### 5.3 解析器（`parse_categories_file` 内部流程）

```
1. std::fs::read_to_string(file_path)
     失败 → 返回 Err("无法读取文件")
2. 编码兜底：若 UTF-8 解析失败，用 GBK 重新解码
     （引入 encoding_rs，或先读 bytes 再尝试两种解码）
3. 按扩展名分发：
   .txt → parse_txt(content)   // 复用 import_preset_categories_into 的分段逻辑
   .json → serde_json::from_str::<Vec<JsonItem>>(content)
4. 校验每条：
   - name 缺失/空 → status=error("分类名不能为空")
   - full_path 为空 → status=error("分类路径为空")
   - 其他 → 进入判重
5. 判重（只读，不写库）：
   parent_id 入参决定顶级判重范围：
   - 从根开始逐级查 categories 表（同 import 的 SELECT 逻辑）
   - 全程命中 → status=skip
   - 任一节点未命中 → status=new
   （注意：预览判重基于"当前库状态"，导入时可能因前序 new 条目改变状态，
     故预览统计为"预期值"，最终以 import 实际结果为准）
6. 汇总返回 ParsedCategories
```

### 5.4 导入器（`import_categories_from_file` 内部流程）

```
1. 同 5.3 步骤 1-3 解析
2. 开启数据库事务（conn.execute("BEGIN TRANSACTION")）
3. 将解析出的每条 full_path 注入现有 import_preset_categories_into 逻辑：
   - 改造：函数加 base_parent_id 参数（默认 None=顶级）
   - 逐级：第一级从 base_parent_id 起挂载
   - 命中 → skip+1；插入 → created+1
   - 单条插入失败 → 记录 error，继续下一条（不中断）
4. COMMIT / ROLLBACK（任一不可恢复错误时）
5. 返回 ImportSummary
```

**改造方案**：不修改现有 `import_preset_categories_into` 签名（避免影响 M20.2 调用方），新增内部函数：

```rust
/// 在 db.rs 内部新增
fn import_category_items_into(
    conn: &rusqlite::Connection,
    items: &[CategoryItem],
    base_parent_id: Option<i64>,
) -> ImportSummary;
```

`import_preset_categories_into` 重构为调用 `import_category_items_into` 的包装（`base_parent_id=None`，同时保持 txt 解析逻辑），实现**复用存量、不破坏既有接口**。

### 5.5 锁与并发

- 沿用现有模式：`DATABASE.lock().map_err(|e| e.to_string())?` 后再取 `conn`
- 导入期间持有锁，防止并发写（本项目为单用户桌面应用，锁粒度足够）

## 7. 错误处理清单

| 场景 | 层 | 行为 |
|------|-----|------|
| 文件不存在/无权限 | 后端 | 返回 `Err`，前端 toast 提示"无法读取文件" |
| 文件为空 | 后端 | 解析出 0 条，提示"文件中没有有效分类" |
| JSON 语法错误 | 后端 | 返回 `Err`（含 serde 错误信息） |
| 单条 name 缺失/为空 | 后端 | status=error，不中断 |
| 单条 name 含 `/` | 后端 | 作为字面 name（不拆段），如含 `/` 且是 .txt 会被分段——.txt 无此问题；.json 的 name 含 `/` 视为普通字符 |
| 单条插入失败（DB） | 后端 | 记录 error，继续后续条目 |
| 导入中途进程崩溃 | 后端 | 事务未提交自动回滚，无脏数据 |
| 父分类下拉选中的分类在导入前被删除 | 前端 | 提交时父 id 失效，后端返回 Err，提示重新选择 |

## 8. 边界情况清单

1. **重复行**：同一文件 `技术/前端开发` 出现两次 → 第 1 条 new，第 2 条 skip（幂等）
2. **父子关系**：文件同时含 `技术/前端开发` 和 `技术/前端开发/Web框架` → 父创建后子直接挂接，created 计数正确（含中间父级）
3. **挂到非顶级父分类**：`parent_id=某分类X`，文件写 `技术/前端开发` → 实际成为 `X/技术/前端开发`，判重基于 X 下子树
4. **父分类本身是 system(id=1)**：下拉中排除 `is_system`，不可选
5. **文件名含中文/空格**：Rust `read_to_string` 用完整路径，无影响
6. **GBK 编码 txt**：UTF-8 失败回退 GBK（D8）
7. **超大文件（>1 万条）**：逐条处理，无一次性全量加载内存问题；前端预览表虚拟滚动或分页（>500 条时）
8. **空 name 段**（`.txt` 如 `技术//前端`）：空段丢弃，与现有逻辑一致
9. **Windows 路径反斜杠 `\`**：`.txt` 中作为普通字符，不参与分隔（仅 `/` 是分隔符）——文档中明确提示用户用 `/`
10. **is_system 误判**：新导入的分类 id 从自增分配，不会 ==1，不会误标为 system

## 11. 风险与待确认

### ⚠️ R1：`explain` 字段无法存储（本稿最重要的风险）

- **事实**：`categories` 表无 `explain` 列；`create_category`/`update_category` 均不写 explain；`get_categories` 恒返回 `None`。**这是既有系统状态，非本次引入。**
- **本稿决策（D5）**：v1 不支持 explain，JSON 解析后忽略该字段，并在文档/UI 提示"说明字段暂不支持导入"。
- **备选方案（需另立项）**：执行 schema 迁移 `ALTER TABLE categories ADD COLUMN explain TEXT`，同时打通 `create_category`/`update_category`/`get_categories` 的 explain 持久化——这属于"分类 explain 字段全链路启用"独立功能，超出本次范围。

### R2：导入时预览与实际可能不一致

- 预览基于"当前库状态"；若同一文件内前序条目创建了父级，后序条目预览时可能被算作 skip 但导入时实际已存在 → **一致**（因为预览按整条 full_path 判重，导入也按同一文件顺序）。
- 真正不一致仅发生在：预览与导入之间，用户通过其他窗口手动新增/删除分类。本应用单窗口，概率极低，且导入结果以实际为准（ImportSummary 是真实值）。**可接受。**

### R3：删除分类的级联问题（既有缺陷，不在本次范围）

- `delete_category` 直接 `DELETE`，未处理有子分类/被项目引用的情况。与导入功能无关，本次不修。
