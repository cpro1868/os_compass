# 分类管理 - 自定义导入功能 设计文档

## 1. 需求背景

分类管理页面目前只支持手动逐个创建/编辑/删除分类。当用户已有大量分类数据（如从外部工具整理的清单、协作分享的分类体系）时，缺乏批量导入手段，效率低。

初始化向导中已存在的"导入预置分类"功能（仓库首次创建时触发）不能复用：
- 时机不同：初始化时库为空，分类管理时已有用户数据
- 用户期望不同：前者"拿到一套结构"，后者"把我准备好的数据加进来"
- 容错要求不同：后者必须保证不破坏已有数据

## 2. 设计决策（已与用户确认）

| 决策项 | 选择 | 说明 |
|--------|------|------|
| 文件格式 | **两种都支持** | `.txt` 路径格式 + `.json` 结构化格式 |
| 冲突策略 | **跳过（默认且唯一）** | 已存在的同名+同父分类自动跳过 |
| 导入位置 | **顶级（默认） + 可选父分类** | 用户可下拉选父分类 |
| 预览功能 | **必须预览** | 确认后才执行 |

## 3. 文件格式规范

### 3.1 路径文本格式 `.txt`

沿用现有 `scripts/preset_categories.txt` 格式，保持一致性：

```
# 注释行：以 # 开头，整行跳过
# 空行：跳过

技术/前端开发/Web框架/React生态
技术/前端开发/Web框架/Vue生态
技术/AI与机器学习/大模型与LLM
商业/金融科技/支付系统
```

**规则**：
- 一行一条分类
- 用 `/` 分隔路径层级
- 自动按层级逐级创建父分类（若父分类不存在）
- 空行、`#` 开头注释行跳过
- 不允许有空段（如 `//技术//`）

### 3.2 JSON 格式 `.json`

```json
[
  {
    "path": ["技术", "前端开发", "Web框架"],
    "name": "React生态",
    "explain": "React 周边生态库（Next/Remix/等）"
  },
  {
    "path": ["技术", "AI与机器学习"],
    "name": "大模型与LLM",
    "explain": "大语言模型相关项目"
  },
  {
    "path": ["商业"],
    "name": "支付系统"
  }
]
```

**规则**：
- `path`：必填，从顶级到该分类的父级路径（不含分类自身 name）
- `name`：必填，该分类名
- `explain`：可选，分类说明
- 顶层数组，根分类的 `path` 可为空数组 `[]` 或省略

**前端识别规则**：按文件扩展名自动选择解析器；扩展名为 `.txt` 走路径解析，`.json` 走 JSON 解析。

## 4. 交互流程（5 步）

```
[分类管理页]
   ↓ 点击头部"导入"按钮（与"新增"按钮并排）
[1. 选文件]
   - 弹窗：选择 .txt 或 .json
   - 限制文件类型过滤
   ↓ 选择后自动解析
[2. 解析结果]
   - 显示解析状态：成功 N 条 / 失败 M 条
   - 若有失败，列出错误明细（行号、原因）
   - 全部失败时禁用"下一步"
   ↓ 点"下一步"
[3. 导入选项]
   - 父分类选择器（默认"顶级"）：
     - 顶级 → 导入到根级
     - 选中某分类 → 整体作为其子分类
   - 显示策略提示："同名已存在分类自动跳过"
   ↓ 点"预览"
[4. 预览]
   - 表格：分类全路径 | 状态（新增 / 跳过）
   - 统计：共 X 条 → 新增 A 条 / 跳过 B 条
   - 跳过列表可展开查看
   ↓ 点"确认导入"
[5. 执行]
   - 进度条（按分类数估算）
   - 完成弹窗：成功导入 X 条，跳过 Y 条
   - 自动刷新分类列表
```

## 5. 后端设计

### 5.1 复用现有逻辑

**复用** `db.rs::import_preset_categories_into()` 的核心逻辑：
- 逐级创建（父不存在先建父）
- 动态分配自增 id（不与用户冲突）
- 按 `name + parent_id` 判断已存在则跳过

**无需重写**，只需调整入口：

### 5.2 新增命令

```rust
#[derive(Debug, Deserialize)]
pub struct ImportCategoriesOptions {
    pub parent_id: Option<i64>,       // None = 顶级；Some(id) = 作为该分类子级
    pub strategy: String,             // 当前固定为 "skip"，预留扩展
}

#[derive(Debug, Serialize)]
pub struct ImportCategoriesResult {
    pub created: u32,                  // 新增数
    pub skipped: u32,                  // 跳过数
    pub errors: Vec<ImportError>,      // 错误明细（行号 + 原因）
}

#[derive(Debug, Serialize)]
pub struct ImportError {
    pub line: usize,                   // 输入文件中的行号（1-based）
    pub path: String,                  // 分类路径
    pub reason: String,                // 错误原因
}

#[tauri::command]
pub async fn import_categories_from_file(
    pool: State<'_, DbPool>,
    path: String,
    options: ImportCategoriesOptions,
) -> Result<ImportCategoriesResult, String>
```

### 5.3 后端流程

```
读取文件内容
   ↓ 按扩展名分发
   ├─ .txt → 路径解析（按 / 拆）
   └─ .json → serde_json 解析
   ↓ 校验（空 name、非法字符等）
   ↓ 进入数据库事务
   ↓ 调用 import_categories_into() 改造版
       - 支持可选 parent_id 覆盖顶级
       - 跳过策略
       - 累积统计 created/skipped
   ↓ 返回结果
```

### 5.4 新增表/字段

**无需新增表/字段**，完全复用现有 `categories` 表。

## 6. 前端设计

### 6.1 新增组件

**`ImportCategoryDialog.tsx`**：分类管理页面专用导入弹窗，含 4 个步骤状态机：

```typescript
type Step = "select" | "parse" | "options" | "preview" | "executing" | "done";
```

### 6.2 修改点

**`CategoryManager.tsx`**：
- 头部"新增"按钮旁增加"导入"按钮
- 导入弹窗状态控制
- 完成后调用 `loadCategories()` 刷新

**`api/category.ts`**：
```typescript
export interface ImportCategoriesOptions {
  parent_id?: number | null;
  strategy: "skip";  // 当前唯一值
}

export interface ImportCategoriesResult {
  created: number;
  skipped: number;
  errors: Array<{ line: number; path: string; reason: string }>;
}

export const categoryApi = {
  // ... 现有方法 ...
  async importFromFile(
    path: string,
    options: ImportCategoriesOptions
  ): Promise<ImportCategoriesResult> {
    return invoke("import_categories_from_file", { path, options });
  },
};
```

### 6.3 前端预览（dry-run）

**复用后端逻辑**——为简化设计，前端不做 dry-run。后端解析阶段即返回"将创建/将跳过"的预览列表。

实际实现调整：
- 后端命令拆为两步：`parse_categories_file`（解析+预览）+ `import_categories_from_file`（执行）
- 或合并为一步，预览通过先解析文件但不写入数据库（前端传解析后的数据数组，后端只校验逻辑）

**最终方案**：后端新增两个命令

```rust
#[tauri::command]
pub fn parse_categories_file(path: String) 
    -> Result<ParsedCategories, String>
// 返回：成功条目 + 错误条目 + 校验通过的总条数

#[tauri::command]
pub fn import_categories(
    items: Vec<CategoryItem>,
    options: ImportCategoriesOptions,
) -> Result<ImportCategoriesResult, String>
// 前端传已解析的条目，后端只负责入库
```

**优势**：
- 前端拿到解析结果后做预览展示
- 用户确认后前端把条目原样回传给后端执行
- 避免后端重复解析

## 7. 错误处理

| 场景 | 处理 |
|------|------|
| 文件不存在 / 无读权限 | 后端返回 IO Error，前端提示"无法读取文件" |
| JSON 格式错误 | 后端返回解析错误，前端展示错误位置 |
| 单条格式错误（如空 name） | 单条跳过，计入 errors 列表，不中断整体导入 |
| 单条数据库错误（如 UNIQUE 冲突） | 单条跳过，计入 errors，继续后续条目 |
| 父分类路径中间断裂 | 自动建中间层级（沿用现有逻辑） |
| 导入过程中断（程序崩溃） | 数据库事务回滚，已导入的也算未导入 |

## 9. 范围之外（不做）

- 不做"导出分类"功能
- 不做"批量删除分类"功能
- 不做"分类合并/重命名"功能（用现有编辑即可）
- 不做 Excel (.xlsx) 格式支持（仅 .txt 和 .json）
- 不做"覆盖"策略（用户已选"仅跳过"）

## 10. 测试要求

### 后端
- 单元测试：路径解析（含中文、含空格、含特殊字符）
- 集成测试：导入 .txt 文件，验证数据库正确写入
- 集成测试：导入 .json 文件
- 集成测试：重复导入 → 全部跳过
- 集成测试：父分类已存在 → 子分类自动追加
- 集成测试：空文件 / 无效 JSON / 错误格式 → 返回 errors 不崩溃

### 前端
- 文件选择 + 类型过滤
- 解析结果展示
- 预览表格正确性
- 父分类切换不影响顶级分类
- 完成后列表刷新

## 11. 验收标准

1. 在分类管理页点"导入"，能选择 .txt 或 .json 文件
2. 解析阶段展示成功/失败明细
3. 选项阶段可选择父分类（默认顶级）
4. 预览阶段展示每个分类的状态（新增/跳过）
5. 执行后正确导入到数据库，分类列表刷新
6. 重复执行同一文件，第二次全部跳过（验证幂等）
7. 不破坏已有分类数据
8. 中英文界面均可用
