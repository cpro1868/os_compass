## 📖 为什么需要 OS-Compass？

在日常开发与技术选型中，开发者常常面临以下困扰：

* 📚 **收藏即吃灰**：GitHub Star、浏览器书签积压数百个，缺乏分类、进度标记与生命周期状态追踪，需要用时根本想不起来；
* 🌍 **验证门槛高**：面对全英文 README、庞杂的代码结构与繁琐的环境配置，往往花费数小时却连 Demo 都跑不起来；
* 🔍 **检索不合拍**：传统基于关键词的搜索只能机械匹配，无法深入理解“找一个轻量级音视频转码库并支持 WebAssembly”这类复杂业务意图；
* ☁️ **云端顾虑重重**：许多管理工具强依赖云端账号，个人知识资产与企业技术储备随时面临服务中断或隐私泄漏的风险。

**OS-Compass（开源罗盘）** 为此而生。它不是一个单纯的书签工具，而是常驻桌面的 **“开源资产智能管家与选型决策智库”**。

## ✨ 核心特性

### 1. 🧭 智能意图搜索 (Intent Search)
* **语义向量检索**：基于本地嵌入模型实现毫秒级余弦相似度匹配，告别机械关键词匹配；
* **多轮对话收敛**：内置专业开源顾问 Prompt，能承接上下文对话、主动推敲深层需求，自动收敛并输出精准推荐结果；
* **大模型直接推荐**：当本地库不匹配时，自动触发大模型全网知识库推荐，直接生成清晰结构化的 Markdown 选型报告。

### 2. 📡 情报雷达 (Radar Inbox)
* **多源动态聚合**：统一监控 GitHub Trending、NPM、PyPI、Crates.io、RSS 与 Telegram 频道的最新开源动态；
* **智能广告过滤**：内置广告过滤模型，自动屏蔽低质宣发与无关推广；
* **永久收藏夹**：区别于有时效性的动态资讯流，收藏夹提供独立的时间管理，确保所有沉淀的技术资产永久可查。

### 3. 🤖 AI 深度分析与 Runbook 生成
* **一键概览透视**：自动提炼项目核心功能、适用场景、技术优缺点；
* **双语对照阅读**：自动清洗并翻译项目 README，彻底扫清语言障碍；
* **AI 快速起步指引 (Runbook)**：自动抽取并排查环境依赖、安装命令与快速运行 Demo 步骤；
* **项目健康度评分**：结合 Star 增长趋势、提交活跃度、Issue 响应速度等综合评估维护状态。

### 4. 🗂️ 全生命周期管理与知识图谱
* **四态生命周期看板**：以看板形式直观管理各个项目的进展：
  * 💡 `待探索 (TO_EXPLORE)`：列入关注，有待调研；
  * 🔬 `深度研究中 (DIVING)`：正在进行 PoC 验证或源码剖析；
  * ✅ `已落地 (IN_USE)`：已集成进公司业务或个人生产系统；
  * 🗑️ `弃用/避坑 (ABANDONED)`：记录不符合预期的原因，避免团队再次踩坑。
* **多层级分类树**：支持技术栈、业务域自由多级归类与批量导入导出。

### 5. 🔒 本地优先与数据主权 (Local-First)
* **数据完全归属本地**：所有项目数据、分类体系、笔记记录均保存在本地 SQLite 数据库中；
* **仓库级隔离机制**：支持建立多个独立仓库（如“个人兴趣”与“公司项目”完全物理隔离）；
* **多层级密钥防护**：用户自定义敏感信息（Token、密钥）通过 AES-256-GCM 硬件级强加密存储，API Key 直连官方，绝不经过第三方代理服务器。

## 🚀 快速上手

### 方式一：下载桌面安装程序（推荐）

1. 前往 GitHub 的 [Releases 页面](../../releases)；
2. 下载适配您系统的最新版本：
   * **Windows 安装版**：`os-compass_x.y.z_x64-setup.exe` 或 `.msi`
   * **便携绿色版**：解压即可直接双击 `os-compass.exe` 运行；
3. 首次启动跟随向导即可完成初始配置。

### 方式二：从源码编译构建

#### 环境准备
* **Node.js** >= 20.0.0
* **pnpm** >= 9.0.0
* **Rust** >= 1.75.0
* **系统编译工具链**：
  * Windows：安装有 C++ 桌面开发的 MSVC 或 MinGW（已安装 MSYS2）

#### 克隆与安装
```bash
# 1. 克隆代码仓库
git clone https://github.com/your-org/os-compass.git
cd os-compass

# 2. 安装前端依赖
cd os-compass
pnpm install

# 3. 本地开发调试运行
pnpm tauri dev

# 4. 编译打包生成可执行文件
pnpm tauri build
```

构建生成的安装包位于：`os-compass/src-tauri/target/release/bundle/`。

## 🏛️ 技术架构

OS-Compass 采用经典的“轻量前端 + 高性能原生内核”架构：

```
┌─────────────────────────────────────────────────────────────┐
│                    用户界面层 (Frontend)                     │
│    React 18 + TypeScript + Tailwind CSS + Zustand + i18next │
└──────────────────────────────┬──────────────────────────────┘
                               │ Tauri IPC (JSON / Binary)
┌──────────────────────────────▼──────────────────────────────┐
│                    原生核心层 (Core / Rust)                 │
│  ┌─────────────────┬───────────────────┬─────────────────┐  │
│  │   生命周期引擎   │   意图搜索与向量  │    情报雷达     │  │
│  │ (Project CRUD)  │  (sqlite-vec/cos) │ (Crawler & RSS) │  │
│  └─────────────────┴───────────────────┴─────────────────┘  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                安全加密服务 (AES-256-GCM)              │  │
│  └───────────────────────────────────────────────────────┘  │
└──────────────────────────────┬──────────────────────────────┘
                               │ WAL 模式高速并发
┌──────────────────────────────▼──────────────────────────────┐
│                    存储层 (Storage / SQLite)                │
│   系统库 (全局配置 plugins.db)  │  仓库库 (业务数据 os_compass.db)│
└─────────────────────────────────────────────────────────────┘
```

* **双库架构分离**：系统全局配置（大模型设置、代理设置）与具体仓库数据（项目明细、标签、笔记）物理隔离，切换仓库互不影响；
* **嵌入式向量计算**：支持 SiliconFlow、OpenAI 等标准 Embedding 接口，在 Rust 内存层高效完成相似度加权排序。

## 🛡️ 数据安全与隐私

我们深刻理解技术资产和开发者私有数据的重要性：

1. **零遥测、无回传**：应用本身没有任何用户行为统计、日志上报或遥测分析组件；
2. **纯本地持久化**：不提供也无需注册任何云端账号，断网环境下绝大部分管理功能正常可用；
3. **凭据安全防护**：大模型 API Key 存储遵循项目 [安全工程方法论](docs/安全工程方法论.md)，严禁将任何明文凭据写入业务数据库或日志文件。
